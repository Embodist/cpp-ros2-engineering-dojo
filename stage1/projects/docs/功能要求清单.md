# 功能要求清单（业务 / 功能）

> **这份文档补什么**：`docs/cpp2.md` 的项目卡只写了「必须实现的类型/接口」+「内功核查点」，缺一层**功能/业务要求**。
> 本清单把每个项目拆成 **对象 → 暴露的方法（能力）→ 功能验收条件**，和内功核查点**分成两栏**：
> - 本清单：验收「**功能对不对、能不能用**」
> - `cpp2.md` 核查点：验收「**内功到不到**」
>
> **类型**：
> - **【应用/系统】** 项目 1 / 10 / 11 / 12 / 13 —— 面向使用者/调用者的功能验收
> - **【库/原语】** 项目 2–9 —— 库的「业务」就是 **API 语义契约**（调用方视角的行为）
>
> **尺度**：只给到 **对象 / 方法名 / 行为要求**，**不给现成签名**。精确的返回类型、参数列表、`const`/`noexcept`
> 是你 `docs/实操手册.md` SOP 第 1 步「写接口草案」的练习——本清单刻意留白。

## 项目 1 · 学生管理系统（三版）【应用/系统】

**对象**

| 对象 | 职责 |
| --- | --- |
| `Student` | 值类型：`id`、`name`、`age`、`scores`（科目→成绩） |
| `Repository` | 管理一组学生，提供增删改查与统计 |
| `Person`（v2 抽象基类） | 派生出 `Student` / `Teacher` |
| `Course`（v2） | 课程，与学生多对多 |
| `App`（可选） | 菜单/CLI 驱动 |

**方法 / 能力**

| 方法 | 做什么（行为要求） |
| --- | --- |
| `add` / `remove` / `update` | 增删改；`id` 冲突需拒绝，字段需校验 |
| `find_by_id` / `find_by_name` | 查找；**返回类型自选**（指针/`optional`/`optional<ref>`），写出取舍 |
| `sort_by(field)` | 按任意字段排序（`ranges::sort` + 投影） |
| `average(subject)` | 某科平均分 |
| `top_n(subject, n)` | 某科前 N 名 |
| `save` / `load` | 持久化（格式自选：CSV/二进制） |
| `clone()`（v2） | 多态拷贝，返回 `unique_ptr<Person>` |
| `import_batch(...)`（v3） | 批量导入，**强异常保证** |

**功能验收条件**

- [ ] 能 `add`/`remove`/`update` 并正确反映在查询结果里
- [ ] `id` 重复、姓名空、成绩越界（非 0–100）都被拒绝
- [ ] 按 `id`/姓名能查到；**查不到返回「空」而非崩溃或悬空**
- [ ] 按任意字段排序结果正确
- [ ] 某科平均分、前 N 名结果正确
- [ ] `save` 后再 `load`，数据一致
- [ ] 加载损坏文件（截断/乱码/非法成绩）不崩溃、不留半成品
- [ ] v2：学生/教师混存；删除学生后关联课程不再指向已销毁对象
- [ ] v3：批量导入中途失败，系统状态回滚到导入前

## 项目 2 · UniquePtr / SharedPtr / WeakPtr【库/原语】

**对象**：`DefaultDelete<T>`、`UniquePtr<T,D>`、`UniquePtr<T[]>`、`SharedPtr<T>`、`WeakPtr<T>`、`MakeUnique`、`MakeShared`（控制块为内部实现）

**方法 / 能力**

| 方法 | 做什么（行为要求） |
| --- | --- |
| `UniquePtr`: `get`/`release`/`reset`/`swap`/`*`/`->`/`bool` | 独占所有权；移动转移，不可拷贝 |
| `UniquePtr<T[]>`: `operator[]` | 数组特化，析构时 `delete[]` |
| `SharedPtr`: 拷贝/移动/`use_count`/`reset`/`swap`/`bool` | 共享所有权，计数增减 |
| `SharedPtr`: 自定义 deleter | 类型擦除，deleter 类型不出现在 `SharedPtr<T>` |
| `WeakPtr`: `lock`/`expired`/`use_count` | 观察，不阻止对象析构 |
| `MakeShared(args...)` | 一次分配放下控制块与对象 |

**功能验收条件**

- [ ] `UniquePtr` 不可拷贝（编译期即失败）
- [ ] 移动后源为空（`get()==nullptr`）
- [ ] `release` 交出所有权后不 delete；`reset` 释放旧对象并接管新对象
- [ ] 自定义 deleter 能管理 `FILE*`（`fclose`）与带状态 lambda
- [ ] `UniquePtr<T[]>` 析构 `delete[]` 全部元素
- [ ] `SharedPtr` 拷贝 `use_count+1`、析构 `-1`；最后一个强引用销毁对象
- [ ] `WeakPtr::lock()` 对象存活时返回有效 `SharedPtr`，否则空
- [ ] `MakeShared` 比 `SharedPtr(new T)` 少一次分配（`operator new` 计数）
- [ ] 循环引用：互持 `SharedPtr` 泄漏；改一方 `WeakPtr` 后正常释放
- [ ] 多线程拷贝/销毁同一对象计数正确（TSan）

## 项目 3 · String（含 SSO）【库/原语】

**对象**：`String`（内部两种存储模式：短串内联 / 长串堆）

**方法 / 能力**

| 方法 | 做什么（行为要求） |
| --- | --- |
| 构造族 | 默认 / `const char*` / `(n,ch)` / `string_view`(explicit) / 拷贝 / 移动 |
| `push_back`/`append`/`+=`/`insert`/`erase`/`clear`/`reserve`/`resize` | 修改；保持 NUL 结尾 |
| `operator[]`/`at`/`front`/`back`/`data`/`c_str`/`size`/`capacity` | 访问 |
| `find`/`substr`/`starts_with`/`ends_with` | 查找与切片 |
| `==`/`<=>`/`operator+`/`operator string_view` | 比较与转换 |

**功能验收条件**

- [ ] 每个修改操作后 `size`、内容、`c_str()`（NUL 结尾）都正确
- [ ] 短串路径**零堆分配**（`operator new` 计数）
- [ ] 别名安全：`s += s`、`s.append(s.c_str())`、`s.insert(0, s)`
- [ ] 含 NUL 字符的串，长度与内容都正确
- [ ] 与 `std::string` 随机操作差分一致（10 万步）

## 项目 4 · List\<T\>（双向链表）【库/原语】

**对象**：`List<T,Alloc>`、内部节点、`iterator`/`const_iterator`/`reverse_iterator`

**方法 / 能力**

| 方法 | 做什么（行为要求） |
| --- | --- |
| `push_front`/`push_back`/`emplace_front`/`emplace_back`/`pop_front`/`pop_back` | 头尾增删 |
| `insert`/`erase`/`clear` | 中间增删 |
| `size` | O(1) 且准确 |
| `splice`/`reverse`/`sort`/`merge`/`unique`/`remove_if` | 算法（`sort` 稳定、不拷贝元素） |
| 迭代器转换 | `iterator` 隐式转 `const_iterator` |

**功能验收条件**

- [ ] 各操作后遍历顺序与 `size` 正确
- [ ] `sort` 稳定
- [ ] `splice` 转移节点**不复制元素**，且迭代器仍有效（属于新链表）
- [ ] `erase` 只让被删迭代器失效
- [ ] 支持 move-only 元素
- [ ] 与 `std::list` 差分一致

## 项目 5 · Vector\<T, Alloc\>（旗舰）【库/原语】

**对象**：`Vector<T,Alloc>`、满足 `contiguous_iterator` 的迭代器

**方法 / 能力**

| 方法 | 做什么（行为要求） |
| --- | --- |
| 构造/赋值族 | 默认 / `(n)` / `(n,v)` / `initializer_list` / 迭代器区间 / 拷贝 / 移动 |
| `size`/`capacity`/`empty`/`reserve`/`shrink_to_fit`/`resize`/`max_size` | 容量 |
| `[]`/`at`/`front`/`back`/`data` | 访问 |
| `push_back`/`emplace_back`/`pop_back`/`insert`/`emplace`/`erase`/`clear`/`assign`/`swap` | 修改 |
| `begin`/`end`/`rbegin`/`rend` | 迭代 |
| `==`/`<=>`/`erase`/`erase_if` | 非成员 |

**功能验收条件**

- [ ] `push_back` 后 `size` 恰好 +1，`capacity` 按增长因子扩展
- [ ] `reserve` 不缩小；`clear`/`resize` 缩小不释放 `capacity`
- [ ] `insert` 返回指向新元素的迭代器，元素顺序正确
- [ ] `push_back(v[0])` 在扩容与不扩容两种情况下都正确
- [ ] `Vector<Vector<int>>` 扩容走移动（`NoexceptToggle` 验证）
- [ ] 空 `vector` 的 `begin()==end()`
- [ ] 与 `std::vector` 随机操作差分一致（10 万步）

## 项目 6 · Arena 与对象池分配器【库/原语】

**对象**：`ArenaResource`（线性 bump）、`PoolAllocator<T>`（固定块 + 空闲链表）

**方法 / 能力**

| 方法 | 做什么（行为要求） |
| --- | --- |
| `ArenaResource`: `allocate(size,align)`/`reset` | 顺序分配，**不支持单块释放** |
| `PoolAllocator<T>`: `allocate`/`deallocate`/相等比较 + `value_type` | 满足 Allocator 要求 |
| 与 `Vector<T,PoolAllocator<T>>`、`List<T,PoolAllocator<T>>` 联用 | 容器接入分配器 |

**功能验收条件**

- [ ] 对齐正确：`max_align_t` 与超对齐（`alignas(64)`）都对
- [ ] 池满行为明确（抛异常或返回失败）并有测试
- [ ] 运行阶段**零 malloc**（`operator new` 计数）
- [ ] `n*sizeof(T)` 溢出时安全失败
- [ ] 接入 `Vector`/`List` 后差分测试仍通过

## 项目 7 · Function\<R(Args...)\>（类型擦除）【库/原语】

**对象**：`Function<R(Args...)>`、`MoveOnlyFunction<R(Args...)>`（内部：SBO 缓冲 / 函数指针表或虚基类）

**方法 / 能力**

| 方法 | 做什么（行为要求） |
| --- | --- |
| 构造 | 存 lambda / 函数指针 / 有状态仿函数；拷贝、移动 |
| `operator()` | 调用；空状态抛 `bad_function_call` |
| `operator bool` | 是否持有可调用对象 |
| `MoveOnlyFunction` | 能存 move-only callable（如捕获 `unique_ptr` 的 lambda） |
| `target<T>()`（选做） | 取回原始 callable |

**功能验收条件**

- [ ] 能存各类可调用对象并正确调用
- [ ] 空调用抛异常；移动后源为空
- [ ] 小 callable **零堆分配**，大 callable 恰好一次分配
- [ ] 捕获引用的 lambda 悬空场景能复现并说明
- [ ] `MoveOnlyFunction` 能存 move-only callable

## 项目 8 · 线程安全队列与线程池【库/原语】

**对象**：`BlockingQueue<T>`（有界/无界）、`ThreadPool`（任务类型用你自己的 `MoveOnlyFunction`）

**方法 / 能力**

| 方法 | 做什么（行为要求） |
| --- | --- |
| `BlockingQueue`: `push`/`pop`(阻塞)/`try_pop`/`close` | 关闭后 `pop` 取完剩余再返回空 |
| `ThreadPool`: `submit(f, args...)` | 返回 `std::future` |
| `ThreadPool`: 优雅关闭 | 析构语义写明（等待完成 or 丢弃） |

**功能验收条件**

- [ ] 多生产者/多消费者，元素**总和不丢、个数正确**
- [ ] 关闭时不死锁、不丢任务
- [ ] 任务抛异常**不杀工作线程**，且能从 `future.get()` 抛出
- [ ] 空闲时 CPU 占用接近 0（无忙等）
- [ ] 从任务里再 `submit` 不死锁（或明确写出限制）

## 项目 9 · SPSC 无锁环形队列【库/原语】

**对象**：`SpscQueue<T,N>`（N 必须为 2 的幂；读写下标分属不同缓存行）

**方法 / 能力**

| 方法 | 做什么（行为要求） |
| --- | --- |
| `try_push` / `try_pop` | 单生产者、单消费者 |
| `empty` / `size_approx` | 状态查询 |

**功能验收条件**

- [ ] 百万元素压力测试，**顺序与内容完全一致**

- [ ] 非平凡类型（含析构、`unique_ptr`）正确构造/析构、不泄漏；队列析构时清理剩余元素
- [ ] 有/无 padding 的吞吐对比（false sharing）
- [ ] TSan 干净

## 项目 10 · 迷你发布订阅与执行器【应用/系统】

**对象**：`Topic<Msg>`、`Publisher<Msg>`、`Subscription<Msg>`（RAII 句柄）、`Executor`（单/多线程）、`Timer`

**方法 / 能力**

| 方法 | 做什么（行为要求） |
| --- | --- |
| `publish` | 以 `shared_ptr<const Msg>` 传递（多订阅者零拷贝） |
| `subscribe` | 返回 RAII 句柄，析构时**自动退订** |
| `Executor`: `spin_once`/`spin`/`stop` | 事件循环 |
| `Timer` | 基于 `steady_clock` 的周期回调 |
| 订阅者队列深度 + 丢弃策略 | 满时丢旧 / 丢新 |

**功能验收条件**

- [ ] 订阅句柄析构后**不再收到回调**，也不崩溃
- [ ] 消息生命周期：最后一个订阅者处理完才释放（析构计数）
- [ ] 慢回调不拖垮其他订阅者（队列深度与丢弃策略生效）
- [ ] 回调里再 publish/subscribe 不死锁
- [ ] 多线程 executor 下 TSan 干净；互斥回调组内回调不并发
- [ ] 定时器漂移：连续 1000 个周期的误差统计

## 项目 11 · 零分配实时控制环【应用/系统】

**对象**：1 kHz 控制循环、模拟传感器线程、模拟执行器线程

**方法 / 能力**

| 能力 | 行为要求 |
| --- | --- |
| 控制环 | 从 SPSC 取传感器数据 → 计算（如 PD）→ 写指令到另一个 SPSC |
| 启动期预分配 | Arena/池在启动阶段分配好，运行期不 new/malloc |
| 周期驱动 | `steady_clock` + `sleep_until`，记录每周期耗时与抖动 |

**功能验收条件**

- [ ] 运行阶段**零分配**（`operator new` 计数为 0）
- [ ] 输出周期误差 p50 / p99 / 最大值
- [ ] 对比：故意加一次 `new` 或 mutex 后，最坏抖动明显变差
- [ ] 控制路径无异常抛出、无意外动态内存

## 项目 12 · 小型数学库【应用/系统】

**对象**：`Vec<T,N>`、`Mat<T,R,C>`、`Quat<T>`、`Transform<T>`（`T` 受 `std::floating_point` 约束）

**方法 / 能力**

| 对象 | 能力 |
| --- | --- |
| `Vec` | 加减、标量乘、点积、叉积（3D）、范数、归一化 |
| `Mat` | 乘法、转置、行列式、逆（3×3、4×4） |
| `Quat` | 乘法、共轭、归一化、`slerp`；与旋转矩阵/轴角/欧拉角互转 |
| `Transform` | 组合、求逆、变换点与向量 |

**功能验收条件**

- [ ] 全部可 `constexpr`（`static_assert` 编译期测试）
- [ ] 与已知值（或 Eigen）对比，double 误差 < 1e-9
- [ ] 边界：零向量归一化、接近 180° 的 `slerp`、万向锁处欧拉角转换
- [ ] `is_standard_layout_v` 与 `is_trivially_copyable_v` 为真

- 打勾规范：本清单每条也要写**证据**（测试名或运行输出），同 `docs/实操手册.md` 第 7 节
- 顺序与节奏：见 `docs/推进清单.md`；为什么这么排：见 `docs/ros2衔接评估.md`
