## 2. 规则到题目映射（核心）

| 范围 | 需要熟练的原则 | 题目 | 机器人场景 |

## 3. 扩展任务补强

扩展任务不改变 60 题主线，只补系统覆盖的空洞：

| ID | 主题 | 补强分区 | 对应缺口 |
|---|---|---|---|
| E01 | 变参模板、SFINAE 与 concepts | T / Con | 模板约束与编译期诊断只有 37、38 两题 |
| E02 | STL 深水区：list、rb_tree、traits、EBO | SL / T | STL 源码只覆盖 vector/deque/unordered_map/iterator |
| E03 | C++20 ranges 与 expected | SL / ES / E | ranges 只有 35，结构化错误只有 07/42 |
| E04 | 并发内存模型：happens-before 与 memory_order | CP | 并发题多，但内存序只有 48 一题 |
| E05 | 测试、CI 与包管理 | SF / T | 缺少生产级测试框架、CI、依赖锁定 |

扩展索引：[`stage1/extensions/README.md`](../stage1/extensions/README.md)。

## 4. 映射质量与使用边界

- **51 条唯一规则里，24 条只出现一次**；覆盖广度够看，但深度不均。
- 复用最多的规则是 `Per.1`（7 题：10、20、31、32、49、56、60）和 `P.9`（4 题：11、19、36、55）。这说明部分映射是**主题级索引**，不是逐条精确对照。
- 12 道骨架题有本地自动测试；48 道开放题依赖你提交 `labs/<ID>/` 代码、`README.md` 和 `evidence.md`。**测试通过或写完任务描述都不等于掌握**。
- 不要把本表当“完成清单”。它的用途是：选题、发现盲区、和官方规则对照。
- 引用规则前回到官方页面核对编号；不要凭记忆写规则编号，也不要把本仓库的映射当成官方认证。
