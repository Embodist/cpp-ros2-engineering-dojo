## 01 ScopeExit 与异常安全 RAII

- 文件：`stage1/include/dojo/scope_exit.hpp`
- 测试：`stage1/tests/test_scope_exit.cpp`
- 结果：7/7（含两个反例），ASan/UBSan 通过

### 目标与不变量

ScopeExit 持有一个清理回调，在作用域结束或异常栈展开时执行。不变量：

1. 每个清理任务恰好执行一次；`release()` 后零次。
2. 移动后源对象不再负责清理；目标对象接管。
3. 移动赋值在覆盖前执行目标原有回调，且只执行一次。
4. 析构函数 `noexcept`；回调不得抛异常，空回调不得调用。

### 完整实现

```cpp
#pragma once
#include <functional>
#include <utility>

namespace dojo {
class ScopeExit {
public:
    explicit ScopeExit(std::function<void()> fn) : fn_(std::move(fn)) {}
    ScopeExit(const ScopeExit&) = delete;
    ScopeExit& operator=(const ScopeExit&) = delete;
    ScopeExit(ScopeExit&& other) noexcept;
    ScopeExit& operator=(ScopeExit&& other) noexcept;
    ~ScopeExit() noexcept;
    void release() noexcept;

private:
    std::function<void()> fn_;
    bool active_ = true;
};

inline ScopeExit::ScopeExit(ScopeExit&& other) noexcept
    : fn_(std::move(other.fn_)), active_(other.active_) {
    other.active_ = false;
}

inline ScopeExit& ScopeExit::operator=(ScopeExit&& other) noexcept {
    if (this != &other) {
        if (active_ && fn_) {
            fn_();
        }
        fn_ = std::move(other.fn_);
        active_ = other.active_;
        other.active_ = false;
    }
    return *this;
}

inline ScopeExit::~ScopeExit() noexcept {
    if (active_ && fn_) {
        fn_();
    }
}

inline void ScopeExit::release() noexcept {
    active_ = false;
}

}  // namespace dojo
```

### 为什么这样写

- `active_` 是显式所有权标志；被移动后的 `std::function` 只保证“有效但值未指定”，不能靠它为空来判断。
- 移动构造必须复制 `other.active_`，而不是无条件 `true`：从已 release 的对象移动，新对象也不该执行。
- 移动赋值必须先执行目标原有回调，再覆盖 `fn_`。`std::function` 的赋值只会销毁旧 callable，不会调用它。
- 析构同时检查 `active_ && fn_`：前者防 release/已移动，后者防空 `std::function` 抛 `std::bad_function_call`。
- 自移动用 `this != &other` 保护。

### 测试推演

| 测试 | 关键路径 |
|---|---|
| scope executes once | 析构 `active_ && fn_` 成立，调用一次 |
| release disables callback | `active_=false`，析构跳过 |
| move transfers ownership | 目标接管，源 `active_=false`，只执行一次 |
| exception unwinding | 栈展开销毁自动对象，析构仍执行 |
| move-assignment disposes previous | 先执行目标旧回调，再接管源回调；每个一次 |
| self move keeps a single cleanup | 自移动保护，无操作；析构仍执行一次 |
| move from released is inert | 源已 release，目标继承 inactive，不执行 |

### 已加入的反例

下面的两个测试已加入 `stage1/tests/test_scope_exit.cpp`，当前测试为 7/7：

```cpp
DOJO_TEST("self move keeps a single cleanup") {
    int n = 0;
    {
        dojo::ScopeExit g([&] { ++n; });
        dojo::ScopeExit& alias = g;
        g = std::move(alias);
    }
    REQUIRE_EQ(n, 1);
}

DOJO_TEST("move from released is inert") {
    int n = 0;
    {
        dojo::ScopeExit a([&] { ++n; });
        a.release();
        dojo::ScopeExit b(std::move(a));
    }
    REQUIRE_EQ(n, 0);
}
```

### 五问卡

- 复杂度：构造/析构/release/移动 O(1)；`std::function` 构造可能有类型擦除开销。
- 异常保证：析构和移动 `noexcept`；callable 必须不抛，否则 terminate。
- 失效/生命周期：被移动对象有效但值未指定且 `active_=false`；回调捕获的引用必须比 guard 活得久。
- 前置条件/UB：callable 不抛；不要捕获局部临时对象的引用；不要复制。
- 不该用的场景：清理动作需要上报错误或按错误类型分支；极热路径可考虑模板 guard。

## 02 UniqueHandle 句柄 RAII

- 文件：`stage1/include/dojo/unique_handle.hpp`
- 测试：`stage1/tests/test_unique_handle.cpp`
- 结果：3/3，ASan/UBSan 通过

### 目标与不变量

封装非负整数句柄和关闭函数；`-1` 表示无效。不变量：

1. 有效句柄在析构时关闭恰好一次。
2. `release()` 返回旧句柄并放弃所有权，不关闭。
3. `reset(v)` 先关闭旧句柄；`reset` 到相同值不重复关闭。
4. 移动转移关闭职责；源对象变为 `-1`。
5. 禁止复制；closer 不得抛异常。

### 完整实现

```cpp
#pragma once
#include <functional>
#include <utility>
namespace dojo {
class UniqueHandle {
public:
    using Closer = std::function<void(int)>;
    explicit UniqueHandle(int handle, Closer closer)
        : value_(handle), closer_(std::move(closer)) {}
    UniqueHandle(const UniqueHandle&) = delete;
    UniqueHandle& operator=(const UniqueHandle&) = delete;
    UniqueHandle(UniqueHandle&& other) noexcept;
    UniqueHandle& operator=(UniqueHandle&& other) noexcept;
    ~UniqueHandle() noexcept;
    int get() const noexcept { return value_; }
    bool valid() const noexcept { return value_ >= 0; }
    int release() noexcept;
    void reset(int value = -1) noexcept;
private:
    int value_ = -1;
    Closer closer_;
};

inline UniqueHandle::UniqueHandle(UniqueHandle&& other) noexcept
    : value_(other.value_), closer_(std::move(other.closer_)) {
    other.value_ = -1;
}

inline UniqueHandle& UniqueHandle::operator=(UniqueHandle&& other) noexcept {
    if (this != &other) {
        if (value_ >= 0 && closer_) {
            closer_(value_);
        }
        value_ = other.value_;
        closer_ = std::move(other.closer_);
        other.value_ = -1;
    }
    return *this;
}

inline UniqueHandle::~UniqueHandle() noexcept {
    if (value_ >= 0 && closer_) {
        closer_(value_);
    }
}

inline int UniqueHandle::release() noexcept {
    const int old = value_;
    value_ = -1;
    return old;
}

inline void UniqueHandle::reset(int value) noexcept {
    if (value == value_) {
        return;
    }
    if (value_ >= 0 && closer_) {
        closer_(value_);
    }
    value_ = value;
}

}  // namespace dojo
```

### 关键点

- `reset(v)` 在 `v == value_` 时直接返回，否则会先关闭再保存同一个原始句柄，析构时二次关闭。
- 移动赋值先关闭目标旧句柄，再接管源；源置 `-1`。
- 析构和 `release/reset` 都是 `noexcept`；closer 抛异常会 terminate，这是契约。
- `closer_` 为空时跳过调用，避免空 `std::function` 抛异常。

### 测试推演

| 测试 | 关键路径 |
|---|---|
| handle closes once | 构造 12，析构 close(12) 一次 |
| release relinquishes ownership | release 返回 7，值变 -1，析构不 close |
| reset and move | reset(2) 先 close(1)；move 后 b 持有 2，析构 close(2) |

### 建议反例

- `reset` 相同值：`h(5, closer); h.reset(5);` 关闭次数仍为 1。
- 从已 release 的对象移动：新对象无效，不关闭。
- 空 closer：有效句柄析构时不调用，不抛。

### 五问卡

- 复杂度：全部 O(1)。
- 异常保证：析构/移动/release/reset `noexcept`；closer 不抛。
- 失效/生命周期：移动后源 `-1`；release 后调用者接管句柄。
- 前置条件/UB：同一句柄不能被两个 UniqueHandle 管理；closer 不抛。
- 不该用的场景：需要共享所有权（用 `shared_ptr`）；句柄关闭可能失败且需要报错。

## 03 MiniVector<T> 内存与异常安全

- 文件：`stage1/include/dojo/mini_vector.hpp`
- 测试：`stage1/tests/test_mini_vector.cpp`
- 结果：5/5，ASan/UBSan 通过

### 目标与不变量

用 `std::allocator<T>` 管理原始存储，只对 `[0, size_)` 构造对象：

1. `size_ <= capacity_`；`[size_, capacity_)` 是未构造的原始内存。
2. `data_ == nullptr` 当且仅当 `capacity_ == 0`。
3. 析构只销毁 `[0, size_)`，再按 `capacity_` 释放。
4. `reserve` 对可复制类型提供强异常保证：失败不改变旧内容。
5. `push_back` 处理别名：扩容前先把参数复制/移动到临时对象。
6. 移动构造/赋值转移缓冲区；源对象清空。

### 完整实现

```cpp
#pragma once
#include <cstddef>
#include <memory>
#include <stdexcept>
#include <utility>

namespace dojo {
template <class T>
class MiniVector {
public:
    MiniVector() = default;
    MiniVector(const MiniVector& other);
    MiniVector& operator=(const MiniVector& other);
    MiniVector(MiniVector&& other) noexcept;
    MiniVector& operator=(MiniVector&& other) noexcept;
    ~MiniVector();
    void reserve(std::size_t new_capacity);
    void push_back(const T& value);
    void push_back(T&& value);
    T& at(std::size_t index) { if (index >= size_) throw std::out_of_range("index"); return data_[index]; }
    const T& at(std::size_t index) const { if (index >= size_) throw std::out_of_range("index"); return data_[index]; }
    std::size_t size() const noexcept { return size_; }
    std::size_t capacity() const noexcept { return capacity_; }
private:
    void destroy_all() noexcept;
    void swap(MiniVector& other) noexcept;

    std::allocator<T> alloc_{};
    T* data_ = nullptr;
    std::size_t size_ = 0;
    std::size_t capacity_ = 0;
};

template <class T>
MiniVector<T>::MiniVector(const MiniVector& other)
    : size_(other.size_), capacity_(other.capacity_) {
    if (capacity_ == 0) return;
    data_ = alloc_.allocate(capacity_);
    std::size_t constructed = 0;
    try {
        for (; constructed < size_; ++constructed) {
            std::construct_at(data_ + constructed, other.data_[constructed]);
        }
    } catch (...) {
        for (std::size_t i = 0; i < constructed; ++i) {
            std::destroy_at(data_ + i);
        }
        alloc_.deallocate(data_, capacity_);
        throw;
    }
}

template <class T>
MiniVector<T>& MiniVector<T>::operator=(const MiniVector& other) {
    if (this != &other) {
        MiniVector tmp(other);
        swap(tmp);
    }
    return *this;
}

template <class T>
MiniVector<T>::MiniVector(MiniVector&& other) noexcept
    : data_(other.data_), size_(other.size_), capacity_(other.capacity_) {
    other.data_ = nullptr;
    other.size_ = 0;
    other.capacity_ = 0;
}

template <class T>
MiniVector<T>& MiniVector<T>::operator=(MiniVector&& other) noexcept {
    if (this != &other) {
        destroy_all();
        data_ = other.data_;
        size_ = other.size_;
        capacity_ = other.capacity_;
        other.data_ = nullptr;
        other.size_ = 0;
        other.capacity_ = 0;
    }
    return *this;
}

template <class T>
MiniVector<T>::~MiniVector() {
    destroy_all();
}

template <class T>
void MiniVector<T>::reserve(std::size_t new_capacity) {
    if (new_capacity <= capacity_) return;

    T* new_data = alloc_.allocate(new_capacity);
    std::size_t constructed = 0;
    try {
        for (; constructed < size_; ++constructed) {
            std::construct_at(new_data + constructed,
                              std::move_if_noexcept(data_[constructed]));
        }
    } catch (...) {
        for (std::size_t i = 0; i < constructed; ++i) {
            std::destroy_at(new_data + i);
        }
        alloc_.deallocate(new_data, new_capacity);
        throw;
    }

    for (std::size_t i = 0; i < size_; ++i) {
        std::destroy_at(data_ + i);
    }
    if (data_) alloc_.deallocate(data_, capacity_);
    data_ = new_data;
    capacity_ = new_capacity;
}

template <class T>
void MiniVector<T>::push_back(const T& value) {
    if (size_ == capacity_) {
        T tmp(value);
        reserve(capacity_ == 0 ? 1 : capacity_ * 2);
        std::construct_at(data_ + size_, std::move_if_noexcept(tmp));
    } else {
        std::construct_at(data_ + size_, value);
    }
    ++size_;
}

template <class T>
void MiniVector<T>::push_back(T&& value) {
    if (size_ == capacity_) {
        T tmp(std::move(value));
        reserve(capacity_ == 0 ? 1 : capacity_ * 2);
        std::construct_at(data_ + size_, std::move(tmp));
    } else {
        std::construct_at(data_ + size_, std::move(value));
    }
    ++size_;
}

template <class T>
void MiniVector<T>::destroy_all() noexcept {
    for (std::size_t i = 0; i < size_; ++i) {
        std::destroy_at(data_ + i);
    }
    if (data_) alloc_.deallocate(data_, capacity_);
    data_ = nullptr;
    size_ = 0;
    capacity_ = 0;
}

template <class T>
void MiniVector<T>::swap(MiniVector& other) noexcept {
    std::swap(data_, other.data_);
    std::swap(size_, other.size_);
    std::swap(capacity_, other.capacity_);
}

}  // namespace dojo
```

### 关键点

- `std::move_if_noexcept` 是强异常保证的核心：只有移动构造 `noexcept` 或类型不可复制时才移动，否则复制。测试里的 `Tracked` 移动是 `noexcept(false)`，所以 reserve 选择复制；注入复制异常时旧元素不动。
- `reserve` 的 catch 只销毁**已经构造完成**的新元素，然后释放新缓冲区并重抛；旧缓冲区完全没动。
- `push_back` 扩容前先构造 `tmp`，避免 `v.push_back(v[0])` 在 reserve 后引用悬空。
- 拷贝赋值用 copy-and-swap：先完整复制，成功后再交换；失败时原对象不变。
- 移动构造/赋值把源指针清空，保证源析构安全。

### 测试推演

| 测试 | 关键路径 |
|---|---|
| push, access, growth | 容量倍增；越界 `at` 抛 `out_of_range` |
| copy is deep | 拷贝构造逐元素复制，修改副本不影响原对象 |
| move-only types | `unique_ptr` 通过 `move_if_noexcept` 选择移动 |
| move container | 移动构造窃取缓冲区，源 size=0 |
| reserve failure | `Tracked` 复制构造抛异常；catch 清理新缓冲区，旧元素保留，`alive` 归零 |

### 建议反例

- 别名扩容：`MiniVector<std::string> v; v.push_back("x"); v.push_back(v.at(0));` 第二次 push 触发扩容，仍应得到两个 "x"。
- 拷贝赋值自赋值：`v = v;` 不泄漏、不改变内容。
- `reserve(0)` 不清空已有元素（reserve 不缩小）。

### 五问卡

- 复杂度：`push_back` 均摊 O(1)，`reserve` O(n)，`at` O(1)。
- 异常保证：reserve 对可复制类型强保证；拷贝赋值强保证；移动操作 `noexcept`。
- 失效/生命周期：任何扩容都会使指针/引用/迭代器失效；`reserve` 后旧地址失效。
- 前置条件/UB：不得对未构造槽位解引用；不得越过 `size_` 访问；allocator 必须匹配分配/释放。
- 不该用的场景：需要稳定地址（用 `std::deque`/节点容器）；异常移动且不可复制类型无法提供强保证。

## 04 MoveOnlyBuffer 零拷贝所有权

- 文件：`stage1/include/dojo/move_buffer.hpp`
- 测试：`stage1/tests/test_move_buffer.cpp`
- 结果：2/2，ASan/UBSan 通过

### 目标与不变量

独占可增长字节缓冲区：

1. 构造与扩容新增字节必须零初始化。
2. `resize` 保留旧内容；缩小时截断；分配失败不改变原缓冲区。
3. `read/write` 越界抛 `out_of_range`。
4. 可移动不可复制；移动后源 `size()==0` 且不拥有数据。
5. `data()/size()` 为 `noexcept`。

### 完整实现

```cpp
#pragma once
#include <cstddef>
#include <cstdint>
#include <memory>
#include <stdexcept>
namespace dojo {
class MoveOnlyBuffer {
public:
    explicit MoveOnlyBuffer(std::size_t size);
    MoveOnlyBuffer(const MoveOnlyBuffer&) = delete;
    MoveOnlyBuffer& operator=(const MoveOnlyBuffer&) = delete;
    MoveOnlyBuffer(MoveOnlyBuffer&& other) noexcept;
    MoveOnlyBuffer& operator=(MoveOnlyBuffer&& other) noexcept;
    void resize(std::size_t new_size);
    std::uint8_t read(std::size_t index) const;
    void write(std::size_t index, std::uint8_t value);
    std::uint8_t* data() noexcept { return data_.get(); }
    const std::uint8_t* data() const noexcept { return data_.get(); }
    std::size_t size() const noexcept { return size_; }
private:
    std::unique_ptr<std::uint8_t[]> data_;
    std::size_t size_ = 0;
};

inline MoveOnlyBuffer::MoveOnlyBuffer(std::size_t n)
    : data_(std::make_unique<std::uint8_t[]>(n)), size_(n) {}

inline MoveOnlyBuffer::MoveOnlyBuffer(MoveOnlyBuffer&& other) noexcept
    : data_(std::move(other.data_)), size_(other.size_) {
    other.size_ = 0;
}

inline MoveOnlyBuffer& MoveOnlyBuffer::operator=(MoveOnlyBuffer&& other) noexcept {
    if (this != &other) {
        data_ = std::move(other.data_);
        size_ = other.size_;
        other.size_ = 0;
    }
    return *this;
}

inline void MoveOnlyBuffer::resize(std::size_t n) {
    auto new_data = std::make_unique<std::uint8_t[]>(n);
    const std::size_t copy_n = n < size_ ? n : size_;
    for (std::size_t i = 0; i < copy_n; ++i) {
        new_data[i] = data_[i];
    }
    data_ = std::move(new_data);
    size_ = n;
}

inline std::uint8_t MoveOnlyBuffer::read(std::size_t index) const {
    if (index >= size_) throw std::out_of_range("index");
    return data_[index];
}

inline void MoveOnlyBuffer::write(std::size_t index, std::uint8_t value) {
    if (index >= size_) throw std::out_of_range("index");
    data_[index] = value;
}

}  // namespace dojo
```

### 关键点

- `std::make_unique<std::uint8_t[]>(n)` 做值初始化，新增字节为 0。
- `resize` 先分配并复制，成功后替换；分配或复制抛异常时旧缓冲区不受影响。
- 移动构造/赋值后源 `size_=0`，`unique_ptr` 自动变空，不会双重释放。
- `read/write` 的边界检查在访问前；越界不触碰内存。

### 测试推演

| 测试 | 关键路径 |
|---|---|
| zero init and access | 构造 4 字节全 0；write(3,42)；write(4) 抛 |
| resize and move | resize(5) 保留 9，新字节 0；move 后源 size=0，目标保留数据 |

### 建议反例

- `resize(0)` 后 `read(0)` 必须抛。
- 移动赋值到已有缓冲区：旧缓冲区释放一次，新数据正确。
- 对 moved-from 对象 `resize(3)`：重新分配，旧数据视为空。

### 五问卡

- 复杂度：构造/访问 O(1)，resize O(n)。
- 异常保证：resize 强保证（先分配后替换）；移动 `noexcept`。
- 失效/生命周期：resize 后旧 `data()` 指针失效；移动后源指针为空。
- 前置条件/UB：不得越过 `size_` 访问；`data()` 在 size=0 时可能为空。
- 不该用的场景：需要共享只读视图（用 `span` 但不延长生命周期）；需要跨线程共享（需额外同步）。
