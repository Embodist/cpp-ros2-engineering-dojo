## 09 ThreadPool 任务执行与关停

- 文件：`stage1/include/dojo/thread_pool.hpp`
- 测试：`stage1/tests/test_thread_pool.cpp`
- 结果：3/3，ASan/UBSan 通过；TSan 在 `setarch -R` 下通过

### 目标与不变量

固定 n 个工作线程；`submit(std::function<int()>)` 返回 `future<int>`：

1. `workers > 0`，否则抛 `invalid_argument`。
2. 任务异常通过 packaged_task 存入 future，由 `get()` 重新抛出。
3. `shutdown` 后拒绝新提交（抛 `runtime_error`），但已接收任务必须执行完。
4. `shutdown` 幂等；析构不 detach，必须 join。
5. 不得持锁执行用户任务；不得在工作线程内调用 `shutdown`（会 join 自己）。

### 完整实现

```cpp
#pragma once
#include <condition_variable>
#include <cstddef>
#include <functional>
#include <future>
#include <mutex>
#include <queue>
#include <stdexcept>
#include <thread>
#include <utility>
#include <vector>
namespace dojo {
class ThreadPool {
public:
    explicit ThreadPool(std::size_t workers) {
        if (workers == 0) throw std::invalid_argument("workers");
        workers_.reserve(workers);
        try {
            for (std::size_t i = 0; i < workers; ++i) {
                workers_.emplace_back(&ThreadPool::run_worker, this);
            }
        } catch (...) {
            shutdown();
            throw;
        }
    }
    ThreadPool(const ThreadPool&)=delete;
    ThreadPool& operator=(const ThreadPool&)=delete;
    ~ThreadPool() { shutdown(); }

    std::future<int> submit(std::function<int()> job) {
        std::packaged_task<int()> task(std::move(job));
        std::future<int> result = task.get_future();
        {
            std::lock_guard<std::mutex> lock(mutex_);
            if (stopping_) throw std::runtime_error("submit after shutdown");
            jobs_.push(std::move(task));
        }
        cv_.notify_one();
        return result;
    }

    void shutdown() noexcept {
        {
            std::lock_guard<std::mutex> lock(mutex_);
            stopping_ = true;
        }
        cv_.notify_all();
        for (auto& worker : workers_) {
            if (worker.joinable()) worker.join();
        }
    }

private:
    void run_worker() {
        for (;;) {
            std::packaged_task<int()> task;
            {
                std::unique_lock<std::mutex> lock(mutex_);
                cv_.wait(lock, [this] { return stopping_ || !jobs_.empty(); });
                if (jobs_.empty()) {
                    if (stopping_) return;
                    continue;
                }
                task = std::move(jobs_.front());
                jobs_.pop();
            }
            task();
        }
    }

    std::mutex mutex_;
    std::condition_variable cv_;
    std::queue<std::packaged_task<int()>> jobs_;
    std::vector<std::thread> workers_;
    bool stopping_=false;
};
}  // namespace dojo
```

### 关键点

- `submit` 在锁内只做“检查停止 + 入队”，用户任务由 worker 在锁外执行。
- `shutdown` 先置 `stopping_` 再 `notify_all`；worker 的退出条件是“已停止且队列为空”，因此已接收任务会先执行完。
- 任务异常不会杀死线程：`packaged_task` 捕获异常并存入 shared state。
- 构造线程失败时调用 `shutdown` 回收已创建线程，避免 `std::terminate`。
- 析构调用 `shutdown`，不 detach；注意不能在 worker 内调用 `shutdown`。

### 测试推演

| 测试 | 关键路径 |
|---|---|
| run and return | 两个任务并发返回 6/7，future 相加 13 |
| exception propagation | 任务抛 runtime_error，future.get 重新抛出 |
| reject after shutdown | shutdown 后 submit 抛 runtime_error |

### 建议反例

- 析构时队列中仍有任务：析构等待任务执行完再 join。
- 重复 shutdown：第二次仍然安全。
- 提交空 `std::function`：任务执行时把 `bad_function_call` 存入 future。

### 五问卡

- 复杂度：submit O(1)；任务调度依赖队列；shutdown O(workers)。
- 异常保证：submit 在关闭后抛；任务异常进 future；线程创建失败时清理。
- 失效/生命周期：future 与 packaged_task 的 shared state 独立于队列；线程池析构前必须停止提交。
- 前置条件/UB：workers >0；不得在 worker 内 shutdown；不要在任务中捕获将销毁的对象。
- 不该用的场景：需要任务优先级/取消（应扩展队列或使用专门调度器）；需要无界并发（固定池会排队）。

## 10 固定容量环形缓冲区

- 文件：`stage1/include/dojo/ring_buffer.hpp`
- 测试：`stage1/tests/test_ring_buffer.cpp`
- 结果：2/2，ASan/UBSan 通过

### 目标与不变量

单线程、固定容量 N 的 FIFO：

1. `try_push` 满时返回 false，不覆盖旧值。
2. `try_pop` 空时返回 `nullopt`。
3. `size() <= N`；`head_` 指向下一出队位置，`tail_` 指向下一入队位置。
4. 使用 `optional<T>` 槽位，不要求 T 默认构造。
5. 严格 FIFO，支持 move-only 类型。

### 完整实现

```cpp
#pragma once
#include <array>
#include <cstddef>
#include <optional>
#include <utility>
namespace dojo {
template<class T, std::size_t N> class RingBuffer {
    static_assert(N>0);
public:
    bool try_push(T value) {
        if (size_ == N) return false;
        items_[tail_].emplace(std::move(value));
        tail_ = (tail_ + 1) % N;
        ++size_;
        return true;
    }

    std::optional<T> try_pop() {
        if (size_ == 0) return std::nullopt;
        std::optional<T> out = std::move(items_[head_]);
        items_[head_].reset();
        head_ = (head_ + 1) % N;
        --size_;
        return out;
    }

    std::size_t size() const noexcept { return size_; }
    static constexpr std::size_t capacity() noexcept { return N; }

private:
    std::array<std::optional<T>,N> items_{};
    std::size_t head_=0;
    std::size_t tail_=0;
    std::size_t size_=0;
};
}  // namespace dojo
```

### 关键点

- `emplace` 在槽位内直接构造 T，避免要求默认构造。
- `try_push` 先检查满，再 emplace；若 emplace 抛异常，`tail_`/`size_` 不变。
- `try_pop` 把 optional 整体移出，再 reset 槽位；move-only T 也能工作。
- `head_/tail_` 用取模环绕；N=1 时两者都为 0，靠 `size_` 区分空/满。
- 满时不覆盖：`size_ == N` 直接返回 false。

### 测试推演

| 测试 | 关键路径 |
|---|---|
| full and wrap | N=2：push 1/2 后满；pop 1；push 4；pop 2/4；空 |
| move only | `unique_ptr` 入队/出队，值 8 保留 |

### 建议反例

- N=1 反复 push/pop，验证环绕。
- 满时 push 返回 false，旧元素仍可 pop。
- 空时 pop 返回 nullopt，不改变 head/tail。

### 五问卡

- 复杂度：push/pop O(1)；空间固定 O(N)。
- 异常保证：emplace 失败时 size 不变；pop 的移动失败时基本保证。
- 失效/生命周期：出队后槽位 reset，旧引用失效；缓冲区地址固定，但元素生命周期随 push/pop。
- 前置条件/UB：单线程使用；N>0；不能并发 push/pop。
- 不该用的场景：多生产者/消费者（需要锁或无锁队列）；需要动态增长（用 deque/vector）。

### 验收

```bash

python3 tools/train.py test 10 --sanitize asan
```

## 11 滑动均值：数值稳定与输入约束

- 文件：`stage1/include/dojo/moving_average.hpp`
- 测试：`stage1/tests/test_moving_average.cpp`
- 结果：2/2，ASan/UBSan 通过

### 目标与不变量

只保留最近 `window` 个有限 double：

1. `window > 0`，否则抛 `invalid_argument`。
2. `push` 拒绝 NaN/Inf，且拒绝时状态不变。
3. `average()` 空返回 `nullopt`。
4. 每次 push 摊还 O(1)。
5. 增量求和会积累浮点误差；周期性从 deque 重算以限制漂移。

### 完整实现

```cpp
#pragma once
#include <cmath>
#include <cstddef>
#include <deque>
#include <optional>
#include <stdexcept>
namespace dojo {
class MovingAverage {
public:
    explicit MovingAverage(std::size_t window) : window_(window) {
        if (window == 0) throw std::invalid_argument("window");
    }

    void push(double value) {
        if (!std::isfinite(value)) throw std::invalid_argument("non-finite");
        values_.push_back(value);
        sum_ += value;
        if (values_.size() > window_) {
            sum_ -= values_.front();
            values_.pop_front();
        }
        if (++since_recalc_ >= window_) {
            sum_ = 0;
            for (double v : values_) sum_ += v;
            since_recalc_ = 0;
        }
    }

    std::optional<double> average() const noexcept {
        if (values_.empty()) return std::nullopt;
        return sum_ / static_cast<double>(values_.size());
    }

    std::size_t count() const noexcept { return values_.size(); }

private:
    std::size_t window_=0;
    std::deque<double> values_;
    double sum_=0;
    std::size_t since_recalc_=0;
};
}  // namespace dojo
```

### 关键点

- 先检查 `isfinite` 再修改状态；NaN/Inf 不会污染 `sum_`。
- 超过窗口时从队首减去旧值，保持 O(1) 增量。
- 每 `window` 次 push 从 deque 重算一次，摊销 O(1)，限制长期误差；也可用 Kahan/Neumaier 补偿。
- `average` 用当前 size 做分母，窗口尚未填满时也正确。
- `count` 返回当前有效值个数，不是总 push 次数。

### 测试推演

| 测试 | 关键路径 |
|---|---|
| sliding window | 2,4 → 3；push 8 后淘汰 2 → (4+8)/2=6 |
| invalid inputs | window=0 抛；Inf/NaN 抛 |

### 建议反例

- window=1：每次 average 等于最后一次 push。
- 负值混合：(-2 + 4)/2 = 1。
- 大量同值 push 后 average 仍相等，验证重算路径。

### 五问卡

- 复杂度：push 摊还 O(1)，average O(1)，空间 O(window)。
- 异常保证：非法输入抛且状态不变；重算不抛。
- 失效/生命周期：deque 元素在淘汰时销毁；average 返回副本。
- 前置条件/UB：window>0；输入必须有限；浮点求和可能溢出到 inf。
- 不该用的场景：需要精确十进制/定点运算（用整数定点）；需要加权均值/方差（扩展公式）。

### 验收

```bash
python3 tools/train.py test 11
python3 tools/train.py test 11 --sanitize asan
```

## 12 CallbackRegistry 重入与生命周期

- 文件：`stage1/include/dojo/callback_registry.hpp`
- 测试：`stage1/tests/test_callback_registry.cpp`
- 结果：4/4，ASan/UBSan 通过；默认 harness 是单线程，GoogleTest 套件已加并发压测并通过 TSan

### 目标与不变量

1. `subscribe` 返回递增非零 Token；拒绝空回调。
2. `unsubscribe` 返回是否曾存在；重复取消返回 false。
3. `publish` 在**不持锁**时调用用户回调。
4. publish 使用快照语义：开始时已注册的回调本轮都调用；同轮中新注册的下轮生效。
5. 回调异常原样传播，且不会把注册表锁住。
6. 回调顺序按 Token 升序（std::map 迭代顺序）。

### 完整实现

```cpp
#pragma once
#include <cstdint>
#include <functional>
#include <map>
#include <mutex>
#include <stdexcept>
#include <utility>
#include <vector>
namespace dojo {
class CallbackRegistry {
public:
    using Token=std::uint64_t;

    Token subscribe(std::function<void(int)> callback) {
        if (!callback) throw std::invalid_argument("empty callback");
        std::lock_guard<std::mutex> lock(mutex_);
        const Token token = next_++;
        callbacks_.emplace(token, std::move(callback));
        return token;
    }

    bool unsubscribe(Token token) {
        std::lock_guard<std::mutex> lock(mutex_);
        return callbacks_.erase(token) != 0;
    }

    void publish(int value) {
        std::vector<std::function<void(int)>> snapshot;
        {
            std::lock_guard<std::mutex> lock(mutex_);
            snapshot.reserve(callbacks_.size());
            for (const auto& entry : callbacks_) {
                snapshot.push_back(entry.second);
            }
        }
        for (const auto& callback : snapshot) {
            callback(value);
        }
    }

private:
    std::mutex mutex_;
    std::map<Token,std::function<void(int)>> callbacks_;
    Token next_=1;
};
}  // namespace dojo
```

### 关键点

- 快照在锁内复制，调用在锁外；回调里 `unsubscribe`/`subscribe` 不会死锁。
- 快照语义：本轮已注册的回调即使中途被取消也会被调用；新注册的不在本轮。
- 回调异常从 `publish` 原样抛出；锁已释放，后续 `unsubscribe/publish` 仍可用。
- `std::map` 按 Token 升序，保证回调顺序。
- `subscribe` 的空回调检查在加锁前；拒绝空 `std::function`。

### 测试推演

| 测试 | 关键路径 |
|---|---|
| ordered subscriptions | 两个回调按 Token 顺序收到 9/10；重复取消 false |
| self unsubscribe and snapshot | 回调内取消自己并注册新回调；本轮 n=1，下轮 n=11 |
| reject empty | `subscribe({})` 抛 |
| callback exception | publish 抛出；之后 unsubscribe/publish 正常 |

### 建议反例

- 回调 A 取消回调 B：B 在本轮快照中仍被调用，下一轮不再调用。
- 回调中注册新回调：下一轮才收到消息。
- 要验证线程安全，新增两个线程并发 subscribe/unsubscribe/publish 的压测，再跑 TSan；现有测试没有线程，不能作为线程安全证据。

### 五问卡

- 复杂度：subscribe/unsubscribe O(log n)；publish O(n) 复制 + O(n) 调用。
- 异常保证：空回调抛；回调异常传播；锁在异常路径自动释放。
- 失效/生命周期：快照中的 `std::function` 是副本；回调捕获的外部对象必须存活到调用结束。
- 前置条件/UB：回调不得销毁注册表本身；Token 唯一；回调内重入 publish 需自行评估递归。
- 不该用的场景：高频 publish 且回调很多（快照复制成本高）；需要严格“取消立即生效”（应改用代际/版本号并在调用前检查）。
