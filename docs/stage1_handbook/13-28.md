## 13 const 与值类别

- 目标：用 8 条声明表达式配合 `static_assert`、`type_traits` 区分 const 引用、指针与左/右值，并实现 const-correct API。
- 核心概念：值类别、`decltype(x)` 与 `decltype((x))`、顶层/底层 const、const 成员函数重载。
- 参考实现思路：断言覆盖普通变量、`std::move`、const 变量、指针自身 const、指向 const，共 8 条；给 `Buffer` 提供 `int* data()` 与 `const int* data() const`，让 const 视图只能读。
- 关键代码片段：

```cpp
#include <type_traits>
#include <utility>
struct Buffer {
    int* data() noexcept { return data_; }
    const int* data() const noexcept { return data_; }
private:
    int data_[4]{};
};
static_assert(std::is_same_v<decltype(std::declval<int&>()), int&>);
static_assert(std::is_same_v<decltype((std::declval<int&>())), int&>);
static_assert(std::is_same_v<decltype(std::move(std::declval<const int&>())), const int&&>);
static_assert(std::is_same_v<decltype(std::declval<Buffer&>().data()), int*>);
static_assert(std::is_same_v<decltype(std::declval<const Buffer&>().data()), const int*>);
```

- 验收证据：`g++ -std=c++20 -c stage1/labs/13/main.cpp` 无输出即通过；反例 `const Buffer cb; cb.data()[0] = 1;` 须编译失败；另测 `int* const` 与 `const int*` 的断言应一真一假。
- 常见坑：混淆 `decltype(x)`/`decltype((x))`；把顶层 const 当底层；按值返回 `const T` 抑制移动；对真正 const 的对象 `const_cast` 后写入是 UB。
- 与 ROS2 的关联（如适用）：订阅回调参数是 const 消息时不要强转修改；需跨回调保存就复制，复制大小直接计入回调延迟。

## 14 初始化与窄化

- 目标：比较 `()`、`{}`、`=` 三种初始化，实现能阻止窄化和溢出的安全整数转换。
- 核心概念：列表初始化的窄化禁令、值初始化与默认初始化、most vexing parse、`std::in_range`。
- 参考实现思路：整理 6 个编译示例：`int a{42}`、`std::uint8_t b{255}` 成功；`int n{3.14}`、`std::uint8_t b{256}`、`unsigned u{-1}` 失败；另比较 `vector<int> v(10)` 与 `v{10}` 的元素个数。转换函数先用 `std::in_range` 检查，再 `static_cast`。
- 关键代码片段：

```cpp
#include <concepts>
#include <cstdint>
#include <stdexcept>
#include <utility>
template<std::integral To, std::integral From>
constexpr To checked_cast(From v) {
    if (!std::in_range<To>(v)) throw std::out_of_range("narrow");
    return static_cast<To>(v);
}
static_assert(checked_cast<std::uint8_t>(255) == 255);
static_assert(!std::in_range<std::uint8_t>(256));
static_assert(!std::in_range<std::uint8_t>(-1));
```

- 验收证据：`g++ -std=c++20 -Wall -Wextra -Wconversion -c stage1/labs/14/main.cpp` 通过；运行版对 `checked_cast<std::uint8_t>(300)` 抛 `std::out_of_range`。反例：`uint8_t x = 300;` 在 `=` 下可静默截断；`int x{3.14};` 必须报窄化。
- 常见坑：`{}` 会优先匹配 `initializer_list`；`()` 可触发 most vexing parse；`static_cast` 静默截断；`std::in_range` 只接受整数类型；浮点转整数需单独检查。
- 与 ROS2 的关联（如适用）：消息字段位宽固定，把传感器值写入前先检查范围；回调里失败应返回错误或日志，不能发布截断值。

## 15 string_view 生命周期

- 目标：设计只借用字符串参数的 parser，构造 view 悬空反例并修正。
- 核心概念：view 不拥有数据、临时对象生命周期、SSO 与堆分配、`c_str()` 的空终止、借用与拥有分离。
- 参考实现思路：parser 入参用 `std::string_view`，只在调用期间读取；若必须保存，类内先拷贝成 `std::string` 再暴露 view。画拥有者/借用者图，并准备一个返回局部 string 的 view 作为 ASan 反例。
- 关键代码片段：

```cpp
#include <memory>
#include <optional>
#include <string>
#include <string_view>
#include <utility>
class Parser {
public:
    explicit Parser(std::string text) : text_(std::move(text)) {}
    std::string_view token() const { return text_; }
private:
    std::string text_;
};
std::string_view bad() {
    std::string local(128, 'x');  // 长串走堆，便于 ASan 报错
    return local;                 // 返回后悬空

```

- 验收证据：`g++ -std=c++20 -g -fsanitize=address stage1/labs/15/main.cpp -o /tmp/a15 && /tmp/a15`，读取 `bad()` 结果应出现 heap-use-after-free；修正版 `Parser` 无报告。反例：`std::string_view v = std::string("tmp");` 悬空；把 `substr` 产生的 view 保存到原串销毁之后。
- 常见坑：假设 view 以 `\0` 结尾；保存回调入参的 view；`data()` 对空 view 可能为空指针；从临时 string 构造 view；误把 `string_view` 当作拥有者。
- 与 ROS2 的关联（如适用）：回调里的消息字段 view 只在回调期间有效；异步处理必须先复制成 `std::string`，否则线程切换后访问已释放缓冲区。

## 16 span 与数组边界

- 目标：用 `std::span` 实现 `max_element` 和 `checksum`，禁止 raw pointer 加长度的隐式约定。
- 核心概念：连续区间、不拥有数据、动态 extent、空区间、子 span、const 正确性。
- 参考实现思路：两个函数都只接收 `std::span`，空输入返回 `nullopt` 或零校验和；用 `subspan` 和不同容器验证同一接口。调用方不能靠 magic 长度参数，长度由 span 携带。
- 关键代码片段：

```cpp
#include <algorithm>
#include <cstdint>
#include <numeric>
#include <optional>
#include <span>
std::optional<int> max_element(std::span<const int> xs) {
    if (xs.empty()) return std::nullopt;
    return *std::ranges::max_element(xs);
}
std::uint32_t checksum(std::span<const std::uint8_t> bytes) {
    return std::accumulate(bytes.begin(), bytes.end(), std::uint32_t{0});
}
```

- 验收证据：`g++ -std=c++20 -c stage1/labs/16/main.cpp` 通过；运行断言 `checksum({}) == 0`、`vector`/`array`/`subspan` 结果一致。反例：`std::span<const int> s = local_vector;` 在 vector 销毁后使用；`span(ptr, 长度偏大)` 越界读，span 不会替你校验。
- 常见坑：返回局部容器的 span；用 `span<int>` 而非 `span<const int>` 导致误写；忽略空输入；`operator[]` 不检查边界；静态 extent 与实参长度不一致。
- 与 ROS2 的关联（如适用）：传感器消息常以 `data()` 加 `size()` 暴露连续缓冲区，可包成 span 做零拷贝算法；但不能把 span 留存到回调结束之后。

## 17 Lambda 捕获与所有权

- 目标：构造异步回调捕获局部变量的故障，用值捕获和 `weak_ptr` 修正，并说明捕获 `this` 何时不安全。
- 核心概念：引用捕获悬空、值捕获拷贝、`this` 生命周期、`weak_ptr::lock`、异步任务拥有关系。
- 参考实现思路：用 `std::function` 模拟延迟回调。故障版返回 `[&]` 捕获局部变量；修复版按值捕获；成员函数场景用 `enable_shared_from_this`，回调捕获 `weak_ptr`，调用时 `lock()` 成功才访问对象。
- 关键代码片段：

```cpp
#include <functional>
#include <memory>
std::function<int()> bad() {
    int local = 42;
    return [&] { return local; };   // local 已亡
}
std::function<int()> good() {
    int local = 42;
    return [local] { return local; };
}
class Session : public std::enable_shared_from_this<Session> {
public:
    std::function<void()> make_task() {
        std::weak_ptr<Session> weak = weak_from_this();
        return [weak] { if (auto self = weak.lock()) self->run(); };
    }
private:
    void run() {}
};
```

- 验收证据：ASan 运行故障版，调用 `bad()()` 应报 stack-use-after-scope；修复版输出 42。反例：异步定时器捕获 `[this]` 后对象先析构；把 `shared_ptr` 存进对象自身成员形成循环。生命周期测试应显式先销毁 owner 再触发回调。
- 常见坑：C++20 起 `[=]` 不再隐式捕获 `this`，需写 `[this]`；`weak_ptr` 必须检查 `lock()`；长期回调持有 `shared_ptr` 会延长对象寿命；引用捕获线程间共享数据有数据竞争。
- 与 ROS2 的关联（如适用）：定时器、订阅回调常捕获节点或组件 `this`；节点销毁后回调仍可能被 executor 调度，应使用弱引用并在回调内快速检查。

## 18 enum class 与状态机

- 目标：设计 Idle/Ready/Running/Error 四态设备状态机，所有非法转换被拒绝，覆盖每条合法边。
- 核心概念：作用域枚举、显式转换、穷举 `switch`、转换表、非法状态。
- 参考实现思路：用 `enum class State` 定义状态，合法边写成 `constexpr` 表；`apply` 返回 `optional<State>`，非法边返回 `nullopt`。对 4×4 全部组合写测试，合法 6 条成功，其余失败，并补充 Error 恢复路径。
- 关键代码片段：

```cpp
#include <optional>
enum class State { Idle, Ready, Running, Error };
struct Edge { State from; State to; };
constexpr Edge kEdges[] = {
    {State::Idle, State::Ready}, {State::Ready, State::Idle},
    {State::Ready, State::Running}, {State::Running, State::Ready},
    {State::Running, State::Error}, {State::Error, State::Idle},
};
constexpr bool can_transition(State a, State b) {
    for (auto e : kEdges) if (e.from == a && e.to == b) return true;
    return false;
}
std::optional<State> apply(State s, State want) {
    return can_transition(s, want) ? std::optional<State>{want} : std::nullopt;
}
```

- 验收证据：运行全组合测试，预期 6 条合法边返回状态、10 条非法边返回 `nullopt`；`static_assert(!can_transition(State::Idle, State::Running));`。反例：Error→Running、Idle→Running、Running→Running 都应拒绝。
- 常见坑：`switch` 漏 `default` 或漏枚举值；`static_cast<State>(99)` 可造出无枚举名的值；只测合法路径；把状态和事件混成一个枚举；忘记处理自环。
- 与 ROS2 的关联（如适用）：生命周期节点状态迁移与此同构；回调中非法转换应拒绝并记录日志，而不是直接赋值状态字段。

## 19 constexpr 与编译时约束

- 目标：实现 constexpr 数据包 magic/version 校验，并用 `static_assert` 建立编译期约束，运行期复用同一函数。
- 核心概念：`constexpr` 函数、常量表达式、立即失败、编译期与运行期同一逻辑、整型字面量。
- 参考实现思路：定义只含 magic 和 version 的 `Header`；`valid` 同时检查 magic 与版本区间；写至少 5 条 `static_assert`（2 正 3 负），再保留一个故意失败的正例作为编译失败证据；运行时从输入构造 Header 调用同一函数。
- 关键代码片段：

```cpp
#include <cstdint>
struct Header { std::uint32_t magic; std::uint16_t version; };
constexpr bool valid(Header h) {
    return h.magic == 0xCAFEBABEu && h.version >= 1 && h.version <= 3;
}
static_assert(valid({0xCAFEBABEu, 1}));
static_assert(valid({0xCAFEBABEu, 3}));
static_assert(!valid({0xDEADBEEFu, 1}));
static_assert(!valid({0xCAFEBABEu, 0}));
static_assert(!valid({0xCAFEBABEu, 4}));
// static_assert(valid({0, 1}), "bad magic");  // 预期编译失败
```

- 验收证据：`g++ -std=c++20 -c stage1/labs/19/main.cpp` 通过；取消注释最后一行后应报 `static assertion failed: bad magic`；运行期输入合法/非法包分别返回真/假。反例：版本 0 和 4 必须拒绝；magic 字节序错误的包必须拒绝。
- 常见坑：magic 字面量漏 `u` 或被窄化；网络字节序未转换；`consteval` 不能运行期调用；常量求值中触发 UB 会直接编译失败；`static_assert` 只能放常量表达式。
- 与 ROS2 的关联（如适用）：消息 magic/version 可在编译期约束常量，运行期仍需校验对端数据；跨平台时先统一字节序再比较。

## 20 结构化绑定与所有权

- 目标：比较结构化绑定 `auto` 与 `auto&` 对大型对象的复制影响，用构造计数和基准量化。
- 核心概念：隐藏对象、绑定名是成员别名、`auto` 拷贝、`auto&` 借用、`auto&&` 延长临时对象寿命。
- 参考实现思路：给大对象实现带计数的拷贝/移动构造；构造 `pair<Big, Big>` 后分别用 `auto`、`auto&`、`const auto&`、`auto&&` 绑定，打印计数差；再用 chrono 在 `-O0` 与 `-O2` 下测耗时，记录环境。
- 关键代码片段：

```cpp
#include <array>
#include <iostream>
#include <utility>
struct Big {
    std::array<int, 1024> v{};
    static inline int copies = 0;
    Big() = default;
    Big(const Big& o) : v(o.v) { ++copies; }
    Big(Big&&) noexcept = default;
};
int main() {
    std::pair<Big, Big> p;
    int before = Big::copies;
    auto [a, b] = p;          // 2 次拷贝
    std::cout << Big::copies - before << '\n';
    before = Big::copies;
    auto& [x, y] = p;         // 0 次
    std::cout << Big::copies - before << '\n';
}
```

- 验收证据：`g++ -std=c++20 -O2 stage1/labs/20/main.cpp -o /tmp/a20 && /tmp/a20` 预期依次输出 `2`、`0`；`auto [c,d] = std::move(p);` 应增加 2 次移动。反例：`const auto [e,f] = p;` 仍拷贝；未定义移动构造时即使 `std::move` 也会退化成拷贝。
- 常见坑：结构化绑定名不是引用类型；`auto&` 不能绑定临时 pair；`auto&&` 绑定临时会延长隐藏对象寿命；只看源码不测计数会被优化误导；`-O2` 可能省略无副作用复制的耗时。
- 与 ROS2 的关联（如适用）：回调里解包大消息字段用 `const auto&` 避免复制；若要把字段留给异步任务，必须拥有或复制，不能保存绑定引用。

## 21 Rule of Zero 对照实验

- 目标：把拥有裸资源的自定义类改写为只持有 `unique_ptr`/`vector` 的 Rule of Zero，验证重复移动和复制行为明确且无 double-free。
- 核心概念：Rule of Zero/Five、隐式移动、`unique_ptr` 只移动、`vector` 值语义、析构抑制移动。
- 参考实现思路：先保留一个有裸指针和默认拷贝的旧版，用 ASan 演示 double-free；再改写为 `vector` 成员，不写析构/拷贝/移动，让编译器生成。用 `static_assert` 检查可拷贝、可移动及 `noexcept` 移动。
- 关键代码片段：

```cpp
#include <cstddef>
#include <type_traits>
#include <utility>
#include <vector>
class Buffer {
public:
    explicit Buffer(std::size_t n) : data_(n) {}
private:
    std::vector<std::byte> data_;
};
static_assert(std::is_copy_constructible_v<Buffer>);
static_assert(std::is_nothrow_move_constructible_v<Buffer>);
int main() {
    Buffer a(16);
    Buffer b = std::move(a);
    Buffer c = b;          // 值语义，安全复制
}
```

- 验收证据：`g++ -std=c++20 -g -fsanitize=address stage1/labs/21/main.cpp -o /tmp/a21 && /tmp/a21` 无报告；旧版默认拷贝加两次析构应报 double-free。反例：手写析构会抑制隐式移动，`Buffer b = std::move(a)` 退化成拷贝；自赋值在旧版可能释放后继续使用。
- 常见坑：写了析构仍以为编译器会生成移动；对 `unique_ptr` 成员类误以为可拷贝；`std::move` 本身不移动；移动后源对象状态有效但未指定；把裸指针放进容器仍可能泄漏。
- 与 ROS2 的关联（如适用）：节点成员用 `unique_ptr`/`vector` 管理发布者、缓冲区，析构顺序自动正确；不要手写 `delete` 管理回调资源。

## 22 异常安全分级

- 目标：为文件替换失败设计 basic/strong/no-throw 三层保证，故障注入后说明旧文件是否仍有效。
- 核心概念：基本/强/不抛保证、提交或回滚、临时文件加原子重命名、RAII 清理、`error_code`。
- 参考实现思路：写入同目录临时文件，成功后 `rename` 原子替换；写失败删除临时文件并抛出，旧文件不变（强保证）。清理和析构用 `error_code`、不抛（no-throw）；跨文件系统 rename 会失败，须说明保证降级。
- 关键代码片段：

```cpp
#include <filesystem>
#include <fstream>
#include <stdexcept>
#include <string_view>
#include <system_error>
void replace(const std::filesystem::path& target, std::string_view bytes) {
    auto tmp = target; tmp += ".tmp";
    {
        std::ofstream out(tmp, std::ios::binary | std::ios::trunc);
        out.write(bytes.data(), static_cast<std::streamsize>(bytes.size()));
        if (!out) { std::filesystem::remove(tmp); throw std::runtime_error("write"); }
    }
    std::error_code ec;
    std::filesystem::rename(tmp, target, ec);   // 同文件系统原子替换
    if (ec) { std::filesystem::remove(tmp); throw std::system_error(ec); }
}
```

- 验收证据：注入写入失败后对旧文件 `sha256sum`，预期哈希不变；成功替换后哈希等于新内容。反例：直接 `ofstream(target, trunc)` 再抛异常会丢旧内容；跨文件系统 rename 失败需清理临时文件。
- 常见坑：只检查 open 不检查 write/close；析构抛异常；rename 不跨文件系统；无 fsync 时掉电可能丢新内容；异常穿过回调边界。
- 与 ROS2 的关联（如适用）：保存参数或地图文件时，服务回调失败不能破坏旧配置；捕获异常并返回错误码，保留旧文件比部分写入更重要。

## 23 引用计数循环

- 目标：用 `shared_ptr` 制造循环引用并用 `weak_ptr` 解除，用析构日志证明泄漏和修复。
- 核心概念：共享所有权、引用计数、循环泄漏、`weak_ptr` 非拥有、`lock()` 提升、父子反向边。
- 参考实现思路：先让父节点和子节点各持有对方 `shared_ptr`，作用域结束后析构日志应完全不出现；再把反向边改为 `weak_ptr`，局部指针释放后两条析构日志都出现。用 LeakSanitizer 佐证故障版。
- 关键代码片段：

```cpp
#include <iostream>
#include <memory>
#include <string>
#include <utility>
struct Node {
    explicit Node(std::string n) : name(std::move(n)) {}
    std::string name;
    std::shared_ptr<Node> child;
    std::weak_ptr<Node> parent;   // 反向边不拥有
    ~Node() { std::cout << "~" << name << '\n'; }
};
int main() {
    auto p = std::make_shared<Node>("p");
    auto c = std::make_shared<Node>("c");
    p->child = c;
    c->parent = p;
    p.reset();
    c.reset();                    // 应看到 p、c 两条析构日志
}
```

- 验收证据：运行修复版预期打印 `~p` 和 `~c` 各一次；把 `parent` 改回 `shared_ptr` 后预期零输出，LSan 报泄漏。反例：`lock()` 后不判空；三节点环仍泄漏；回调捕获 `shared_ptr` 存进对象自身成员也会成环。
- 常见坑：只把一条边改弱而其他边仍成环；误以为 `weak_ptr` 能直接访问成员；长期缓存 `shared_ptr` 延长寿命；在析构中依赖对方仍存活。
- 与 ROS2 的关联（如适用）：父节点/子节点、组件与回调注册表之间的反向引用用 `weak_ptr`；否则 executor 持有的回调可能让节点永不析构。

## 24 工厂返回资源

- 目标：设计 `make_device()` 返回 `unique_ptr`，禁止裸 `new` 在调用边界传播，保证异常路径也关闭资源。
- 核心概念：工厂函数、独占所有权、`make_unique`、异常安全、移动语义、虚析构。
- 参考实现思路：抽象 `Device` 定义虚析构和 `open()`；工厂内先 `make_unique<Derived>`，再调用可能抛异常的 `open()`；局部 `unique_ptr` 在异常时自动析构。用 `static_assert` 固定返回类型，并验证不可拷贝。
- 关键代码片段：

```cpp
#include <cstdio>
#include <memory>
#include <type_traits>
struct Device {
    virtual ~Device() = default;
    virtual void open() = 0;
};
struct Sensor final : Device {
    ~Sensor() override { std::puts("Sensor closed"); }
    void open() override {}
};
std::unique_ptr<Device> make_device() {
    auto d = std::make_unique<Sensor>();
    d->open();                 // 抛异常时 d 自动释放
    return d;
}
static_assert(std::is_same_v<decltype(make_device()), std::unique_ptr<Device>>);
```

- 验收证据：`g++ -std=c++20 -g -fsanitize=address stage1/labs/24/main.cpp -o /tmp/a24 && /tmp/a24` 预期打印一次关闭日志且无泄漏；让 `open()` 抛异常再跑，仍应关闭。反例：`Device* d = make_device().release();` 泄漏；`shared_ptr<Device>(new Sensor)` 多一次分配且异常时不安全。
- 常见坑：基类析构非虚；调用 `.release()` 后忘记接管；工厂返回裸指针；`make_unique` 后方括号误写成 `new Sensor`；在调用方保存 `get()` 的裸指针越过 owner 生命周期。
- 与 ROS2 的关联（如适用）：工厂创建发布者、组件或驱动对象时返回 `unique_ptr`，构造失败自动清理；再把所有权交给节点或容器，避免回调边界泄漏。

## 25 继承析构陷阱

- 目标：构造基类指针删除派生实例的资源泄漏/UB，并修正为虚析构，确认派生资源恰好析构一次。
- 核心概念：多态删除、虚析构、切片、`final`、未定义行为、删除器。
- 参考实现思路：基类先不写虚析构，派生类持有 `unique_ptr` 并在析构打印；`unique_ptr<Base>` 指向派生对象，故障版不执行派生析构。给基类加 `virtual ~Base() = default` 后恢复，并文档说明是否允许多态删除。
- 关键代码片段：

```cpp
#include <cstdio>
#include <memory>
struct Base {
    virtual ~Base() = default;   // 删除本行即触发 UB/资源不析构
    virtual void run() = 0;
};
struct Derived final : Base {
    std::unique_ptr<int> res = std::make_unique<int>(7);
    ~Derived() override { std::puts("~Derived"); }
    void run() override {}
};
int main() {
    std::unique_ptr<Base> p = std::make_unique<Derived>();
    p->run();
}   // 预期恰好打印一次 ~Derived
```

- 验收证据：修复版恰好打印一次 `~Derived`；去掉虚析构后 ASan 应报 new-delete-type-mismatch 或泄漏。反例：切片需要具体基类；本卡基类含纯虚函数，`Base b = Derived{};` 本身编译失败。另用 `struct CB { virtual ~CB()=default; }; struct CD:CB{ int x; }; CB b = CD{};` 演示派生部分被切掉。`shared_ptr<Base> sp = std::make_shared<Derived>();` 的控制块保存正确删除器，基类无虚析构也能析构派生，但不能据此省虚析构。
- 常见坑：`shared_ptr` 删除器可替代虚析构；基类析构调用纯虚函数；`final` 类仍可经基类删除；虚析构影响 ABI；析构默认 `noexcept`。
- 与 ROS2 的关联（如适用）：插件、回调基类、组件接口若通过基类指针销毁，必须虚析构；否则卸载插件时派生资源不释放。

## 26 std::move 并非移动

- 目标：实验 `std::move(const T)` 与移动构造 `noexcept` 对 `vector` 扩容的影响，记录拷贝/移动次数并解释原因。
- 核心概念：`std::move` 只是右值转换、const 右值绑定到 const 左值引用、`move_if_noexcept`、扩容的强保证、NRVO。
- 参考实现思路：给被测类型加拷贝/移动计数，分别提供 `noexcept` 与非 `noexcept` 的移动构造；用 `reserve(1)` 后连续 `push_back` 触发多次扩容。再对 const 对象 `std::move`，观察实际走拷贝。记录编译器、优化级别和输出。
- 关键代码片段：

```cpp
#include <iostream>
#include <utility>
#include <vector>
struct T {
    static inline int copies = 0, moves = 0;
    T() = default;
    T(const T&) { ++copies; }
    T(T&&) noexcept { ++moves; }   // 去掉 noexcept 再跑一次
};
int main() {
    std::vector<T> v;
    v.reserve(1);
    for (int i = 0; i < 8; ++i) v.push_back(T{});
    const T c;
    T x{std::move(c)};             // const 右值 -> 拷贝构造
    std::cout << "copies=" << T::copies << " moves=" << T::moves << '\n';
}
```

- 验收证据：`g++ -std=c++20 -O2 stage1/labs/26/main.cpp -o /tmp/a26 && /tmp/a26`，`noexcept` 版移动次数明显更多；去掉 `noexcept` 后扩容改为拷贝，`copies` 上升。反例：`return std::move(local);` 抑制 NRVO；移动后继续读源对象；对 const 对象 `std::move` 仍拷贝。
- 常见坑：移动构造只在实现处写 `noexcept`、声明处漏写；移动赋值也需 `noexcept`；`move_if_noexcept` 在类型不可拷贝时才强制移动；`std::move` 不清空源对象；自移动赋值需防护。
- 与 ROS2 的关联（如适用）：大消息进出队列时，移动构造是否 `noexcept` 决定容器扩容是搬还是拷，直接影响回调延迟；发布接口通常接收 const 引用，不能靠 `std::move` 省拷贝。

## 27 临时对象引用悬挂

- 目标：复现返回局部 view/reference 的悬挂错误，重构为拥有值的 API，并给出所有权图。
- 核心概念：返回局部引用、生命周期延长不跨函数返回、`string_view`/`span` 借用、值语义、NRVO。
- 参考实现思路：先写 `const std::string&` 和 `std::string_view` 两个故障函数返回局部 string；调用后读取触发 ASan。修复为按值返回 `std::string`，或让调用方传入输出容器；若类暴露内部串，须确保对象拥有且文档写明有效期。
- 关键代码片段：

```cpp
#include <iostream>
#include <string>
#include <string_view>
std::string_view bad() {
    std::string local(128, 'a');  // 长串走堆
    return local;                 // 返回后悬空
}
std::string good() {
    return std::string(128, 'a'); // 值语义，拥有结果
}
struct Holder {
    std::string text;
    std::string_view view() const { return text; }
};
int main() {
    auto v = bad();
    std::cout << v[0] << '\n';    // ASan: use-after-free
}
```

- 验收证据：`g++ -std=c++20 -g -fsanitize=address stage1/labs/27/main.cpp -o /tmp/a27 && /tmp/a27` 应报 heap-use-after-free；改用 `good()` 后无报告。反例：`const auto& r = bad();` 不会延长跨返回值寿命；返回局部 vector 的 span 同样悬空。
- 常见坑：以为 `const&` 绑定能延长函数返回的临时对象；短字符串走 SSO 时 ASan 可能不报，要用长串；返回成员引用时对象先亡；`c_str()` 指向临时 string；只读测试未实际访问悬挂内存。
- 与 ROS2 的关联（如适用）：不要返回指向临时消息或局部缓冲区的 view；异步发布前把数据复制进拥有的消息对象，避免 executor 延迟执行时读到已释放内存。

## 28 pImpl 与 ABI 边界

- 目标：用 pImpl 隔离第三方头与实现，验证实现改动不破坏调用方编译。
- 核心概念：实现指针、前向声明、不完整类型、类外析构/移动、编译防火墙、ABI 稳定。
- 参考实现思路：公开头只放 `struct Impl;` 和 `unique_ptr<Impl>`，第三方头只在 `.cpp` 包含；析构和移动操作须在 `Impl` 完整处类外定义。两个调用方 TU 共用公开头，只改 `Impl` 后验证调用方无需重编。
- 关键代码片段：

```cpp
// public header
#include <memory>
class Widget {
public:
    Widget();
    ~Widget();
    Widget(Widget&&) noexcept;
    Widget& operator=(Widget&&) noexcept;
    void step();
private:
    struct Impl;
    std::unique_ptr<Impl> impl_;
};
// implementation TU: include third-party header only here
struct Widget::Impl { /* third-party type and private fields */ };
Widget::Widget() : impl_(std::make_unique<Impl>()) {}
Widget::~Widget() = default;
Widget::Widget(Widget&&) noexcept = default;
Widget& Widget::operator=(Widget&&) noexcept = default;
void Widget::step() { /* impl_->... */ }
```

- 验收证据：`g++ -std=c++20 -c stage1/labs/28/main.cpp`（第二个调用方 TU 与实现 TU 用同样命令）通过；改 `Impl` 后只重编实现 TU 并链接，调用方无需重编。反例：公开头里析构写成 `= default`，调用方会报不完整类型；公开头包含第三方头后，第三方一改，所有包含者重编。
- 常见坑：`unique_ptr<Impl>` 析构/移动未类外定义；拷贝需手写深拷贝；pImpl 多一次分配和间接访问；const 成员仍可改 `Impl`。
- 与 ROS2 的关联（如适用）：库对外接口隐藏 rclcpp/DDS 头文件可减少下游编译依赖；插件或 ABI 边界用 pImpl 隔离实现变更，但回调热路径要计入间接调用成本。
