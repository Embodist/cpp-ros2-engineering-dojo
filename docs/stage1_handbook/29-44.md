## 29 unordered_map 的失效规则

- **目标**：实测 insert、erase、rehash 对 iterator/reference/pointer 三类句柄的失效差异，产出精确规则表。
- **核心概念**：unordered_map 是节点式容器。rehash 只重排桶指针、不搬节点，故迭代器失效而元素引用/指针仍有效；insert 仅在触发 rehash 时使迭代器失效；erase 只失效被删元素的迭代器与引用。
- **参考实现思路**：先 reserve 避免意外 rehash；保存 `it` 与 `&it->second`；分三组实验：未 rehash 的 insert、强制 rehash、erase 其他元素与 erase 当前元素。用 `bucket_count()` 变化证明是否 rehash，每组只使用规则允许的句柄，最后写成规则表。
- **关键代码片段**：

```cpp
std::unordered_map<int, std::string> m;
m.reserve(1000);                       // 预留桶，普通插入不再 rehash
m.emplace(1, "a");
auto it = m.find(1);
const std::string* p = &it->second;
for (int i = 2; i < 500; ++i) m.emplace(i, "x");
assert(it->first == 1 && p->size() == 1);  // 迭代器、引用均有效
m.rehash(4096);                            // 强制 rehash
assert(p->size() == 1);                    // 引用仍有效，it 已失效
auto next = m.erase(m.find(1));            // erase 返回后继迭代器
(void)next;
```

- **验收证据**：`g++ -std=c++20 -O2 -fsanitize=address,undefined -g stage1/labs/29/main.cpp`，输出前后 `bucket_count` 与各断言。反例一：rehash 后解引用旧 `it` 是 UB，但节点通常未释放，ASan 不保证报告；应靠 `_GLIBCXX_DEBUG` 或规则表判定。反例二：循环中 erase 后仍 `++it`，崩溃或漏元素。
- **常见坑**：把“引用仍有效”误当成“迭代器仍有效”；erase 返回后继，不能再自增；reserve 后被超出仍会 rehash。
- **与 ROS2 的关联**：回调间缓存消息迭代器/引用时，另一线程插入触发 rehash 即失效；跨回调应持值或智能指针，并明确锁边界。

## 30 排序与严格弱序

- **目标**：为事件的时间戳/优先级设计比较器，证明满足严格弱序，且同值与极端输入下结果确定。
- **核心概念**：严格弱序要求不可自反、非对称、传递，且等价关系可传递；用 `<=` 会破坏它。同值可用额外序号定平局；浮点时间戳要拒绝 NaN。
- **参考实现思路**：用 `std::tie` 字典序（时间→优先级→seq）形成确定全序。随机三元组验证传递性，覆盖全相等、单元素、逆序、大量同时间戳；优先级“值大优先”显式比较，不取负。
- **关键代码片段**：

```cpp
struct Event { std::int64_t ts; int priority; std::uint64_t seq; };
auto cmp = [](const Event& a, const Event& b) {
    return std::tie(a.ts, a.priority, a.seq) <
           std::tie(b.ts, b.priority, b.seq);
};
std::vector<Event> v{{10, 1, 0}, {10, 1, 1}, {9, 5, 2}};
std::sort(v.begin(), v.end(), cmp);
assert(!cmp(v[0], v[0]));             // 不可自反
assert(cmp(v[1], v[2]));              // seq 打破平局
auto cmp_no_seq = [](const Event& a, const Event& b) {
    return std::tie(a.ts, a.priority) < std::tie(b.ts, b.priority);
};
assert(!cmp_no_seq(v[1], v[2]) && !cmp_no_seq(v[2], v[1])); // 无 seq 时等价
```

- **验收证据**：`-D_GLIBCXX_DEBUG` 下非法比较器常触发断言；反例一：`return a.ts <= b.ts;` 让相等元素互“小于”，结果不确定；反例二：只比时间戳，验证两事件是“等价”而非“相等”。记录随机用例输出。
- **常见坑**：使用 `<=`；浮点 NaN；比较器捕获可变状态；优先级取负溢出。
- **与 ROS2 的关联**：按消息时间戳排序/去重时，非法比较器会让 sort 或优先队列行为未定义；融合多传感器同戳消息必须有确定平局规则。

## 31 deque vs vector 数据通路

- **目标**：用 vector 与 deque 分别模拟消息队列，给出数据规模、p50/p99 延迟、复制次数与内存行为。
- **核心概念**：deque 头尾 O(1)、分段连续；vector 尾插均摊 O(1)，但头部删除 O(n) 并搬移元素。消息队列用 vector 时应“读下标 + 周期压缩”，不要反复 `erase(begin())`；vector 扩容有峰值复制。
- **参考实现思路**：固定 256B 消息体与 N=1e5；同一 bench 模板分别传 `erase(begin())` 与 `pop_front()`；每轮用 steady_clock 计时，收集样本排序取 p50/p99；用可计数 payload 统计拷贝/移动，另记 RSS。至少重复 3 次并写明环境。
- **关键代码片段**：

```cpp
struct Msg { std::uint64_t seq; std::array<std::byte, 256> payload; };
template <class Q, class Pop>
void bench(Q& q, Pop pop, int n) {
    std::vector<std::uint64_t> ns; ns.reserve(n);
    for (int i = 0; i < n; ++i) {
        auto t0 = std::chrono::steady_clock::now();
        q.push_back(Msg{static_cast<std::uint64_t>(i), {}});
        pop(q);
        auto t1 = std::chrono::steady_clock::now();
        ns.push_back(std::chrono::duration_cast<std::chrono::nanoseconds>(t1 - t0).count());
    }
    std::sort(ns.begin(), ns.end());
    std::cout << "p50=" << ns[ns.size() * 50 / 100] << "ns p99=" << ns[ns.size() * 99 / 100] << "ns\n";
}
```

- **验收证据**：`g++ -std=c++20 -O2 stage1/labs/31/main.cpp`，输出含 N、p50、p99、拷贝次数、RSS。反例一：vector `erase(begin())` 在 N=1e6 时 p99 随队列长度线性上升；反例二：只在短队列测，掩盖 O(n)；反例三：未 reserve 的扩容造成长尾。
- **常见坑**：把尾插均摊 O(1) 当成所有操作 O(1)；只测时间不测拷贝；不固定 CPU/优化级别；消息体过小使结论失真。
- **与 ROS2 的关联**：高频回调里对缓存 `erase` 头部会放大延迟；deque 或环形缓冲更贴近固定容量消息队列，同时要考虑 QoS 丢弃策略。

## 32 哈希碰撞实验

- **目标**：手写简化哈希表（开放寻址或链地址），注入大量碰撞，观察负载因子与最坏探测长度，验证 rehash 正确。
- **核心概念**：负载因子=元素数/桶数；线性探测有主聚集，最坏 O(n)；rehash 必须按新容量重算 home 桶；链地址最坏退化为链表。碰撞可用常量 hash 注入。
- **参考实现思路**：选开放寻址、线性探测、不做删除（避免墓碑）；阈值 0.7 翻倍；记录每次插入与最大探测次数。常量 hash 让 n 个键落同一 home，观察 1..n，再与正常 hash 对比；rehash 逐元素迁移。
- **关键代码片段**：

```cpp
struct OpenTable {
    std::vector<std::optional<std::pair<int, int>>> slots{8};
    std::size_t size = 0;
    std::size_t home(int k) const { return std::hash<int>{}(k) % slots.size(); }
    void rehash(std::size_t cap) {
        auto old = std::move(slots);
        slots.assign(cap, std::nullopt); size = 0;
        for (auto& s : old) if (s) insert(s->first, s->second);
    }
    void insert(int k, int v) {
        if ((size + 1) * 10 > slots.size() * 7) rehash(slots.size() * 2);
        auto i = home(k);
        while (slots[i] && slots[i]->first != k) i = (i + 1) % slots.size();
        if (!slots[i]) { slots[i] = std::pair{k, v}; ++size; }
        else slots[i]->second = v;
    }
};
```

- **验收证据**：输出 `n, cap, load, max_probe, avg_probe`；常量 hash 下 max_probe 随 n 线性增长，正常 hash 接近常数。反例一：rehash 只扩数组不重算下标，find 失败；反例二：表满后探测不终止，需先扩容。
- **常见坑**：忘记取模；容量为 0/1；删除留墓碑未处理；rehash 异常导致半迁移；把 hash 质量与表实现正确性混为一谈。
- **与 ROS2 的关联**：以节点名/话题名为键的注册表在实体很多时可能碰撞，最坏情况拖慢发现或分发，应监控负载因子而非只看平均。

## 33 迭代器失效实战

- **目标**：在“删除无效数据帧”中正确使用 erase-remove_if 或 erase 返回值，做到不漏删、不触碰失效迭代器。
- **核心概念**：vector::erase 使被删位置及其后的迭代器/引用失效；remove_if 只把保留元素前移并返回新逻辑末尾，不改变 size；erase-remove 一次搬移完成批量删除；C++20 可用 `std::erase_if`。
- **参考实现思路**：`Frame{id, valid}`；构造首、尾、连续无效帧的样例；先写 `it = erase(it)` 循环并测试，再写 remove_if 版本比较输出；覆盖全无效、全有效、空容器。记录删除后有效 id 序列作为黄金结果。
- **关键代码片段**：

```cpp
struct Frame { std::uint32_t id; bool valid; };
std::vector<Frame> frames = make_frames();
frames.erase(std::remove_if(frames.begin(), frames.end(),
                            [](const Frame& f) { return !f.valid; }),
             frames.end());
for (auto it = frames.begin(); it != frames.end(); ) {
    if (it->id == 0) it = frames.erase(it);  // 用返回的后继
    else ++it;                               // 绝不对已删迭代器自增
}
assert(std::ranges::all_of(frames, [](const Frame& f) { return f.valid; }));
```

- **验收证据**：断言删除后全部 valid 且 id 序列等于预期。反例一：range-for 中 erase 后继续循环，`_GLIBCXX_DEBUG` 或逻辑断言抓到失效，ASan 不保证报告（vector 缓冲区通常未释放）；反例二：remove_if 后忘 erase 尾部，size 不变且残留无效元素；反例三：erase 后对旧迭代器自增导致跳过元素。
- **常见坑**：erase 返回后继不能自增；remove_if 只移动不删除；谓词有副作用；list 应优先用成员 `remove_if`。
- **与 ROS2 的关联**：回调过滤坏帧应避免逐条 erase 的 O(n²)；批量删除后一次性发布，共享容器时注意锁与迭代器寿命。

## 34 optional vs magic number

- **目标**：把以 -1/0xFFFF 表示失败的 API 改为 optional/variant，使合法 -1 可表达，错误路径完整。
- **核心概念**：魔法值把值域与状态耦合；`optional<T>` 表达有无，`variant<T,E>` 在失败时携带类型化原因；二者通常不堆分配，但 optional 无错误细节；C++20 不允许 `optional<T&>`。
- **参考实现思路**：定义 `SensorError`；`optional<int> read_raw()` 表示可能无值；需要原因时用 `variant<int, SensorError>`。旧接口写适配层并标注弃用。测试矩阵：合法 -1、合法 0、失败、超范围；成功路径断言 `*v == -1`，失败路径走错误分支。
- **关键代码片段**：

```cpp
enum class SensorError { Timeout, Disconnected };
std::optional<int> read_raw();                  // nullopt 表示失败
std::variant<int, SensorError> read_checked();  // 失败带原因
void use() {
    if (auto v = read_raw()) {
        assert(*v >= -1);            // -1 是合法读数，不再表示失败
    }
    auto r = read_checked();
    if (auto p = std::get_if<int>(&r)) std::cout << *p;
    else std::cout << static_cast<int>(std::get<SensorError>(r));
}
```

- **验收证据**：四个用例分别输出状态与值。反例一：仍用 `value == -1` 判失败，误判合法 -1；反例二：对空 optional 解引用是 UB，但 ASan/UBSan 通常不报告（存储仍在对象内），应用 `value()`/先查 `has_value()`，或开 `_GLIBCXX_ASSERTIONS` 观察断言；反例三：写 `optional<int&>` 编译失败，应改 `optional<reference_wrapper<int>>`。
- **常见坑**：`value()` 抛 bad_optional_access，`*`/`->` 不检查；variant 类型访问错抛 bad_variant_access；默认构造 optional 为空；丢弃错误细节。
- **与 ROS2 的关联**：驱动/参数读取“无数据”用 optional 比哨兵值清晰；回调失败应显式发布错误或日志，别让哨兵值流入下游。

## 35 投影与 ranges

- **目标**：用 ranges/算法完成传感器记录的筛选、转换、聚合，输出与朴素实现完全一致，并记录 view 寿命。
- **核心概念**：view 惰性、轻量、引用底层范围；filter/transform 不复制元素；投影让算法按成员排序或取极值。C++20 没有 `ranges::fold_left`（C++23），聚合用 `accumulate`。view 不能比底层容器活得久。
- **参考实现思路**：`SensorRecord{ts, temp, valid}`；filter 保留 valid，transform 取温度，accumulate 求和/计数，`ranges::max_element` 配成员投影找最新记录。再写一份手写循环逐项比较。view 限制在同一作用域，返回时物化为容器。
- **关键代码片段**：

```cpp
struct SensorRecord { std::int64_t ts_ms; double temp_c; bool valid; };
std::vector<SensorRecord> recs{{10, 20.0, true}, {20, -1.0, false}, {30, 21.0, true}};
auto hot = recs | std::views::filter([](const SensorRecord& r) { return r.valid; })
                | std::views::transform([](const SensorRecord& r) { return r.temp_c; });
double sum = std::accumulate(hot.begin(), hot.end(), 0.0);  // C++20 用 accumulate
auto newest = std::ranges::max_element(recs, {}, &SensorRecord::ts_ms);  // 投影
assert(newest->ts_ms == 30);
```

- **验收证据**：断言 ranges 结果与朴素循环逐项相等。反例一：返回局部 vector 上的 transform view，调用方读取时悬垂，ASan 报错；反例二：遍历 view 时修改底层容器，迭代器失效；反例三：误用 C++23 的 `fold_left` 导致 C++20 编译失败。
- **常见坑**：把 view 当容器跨界保存；transform 带副作用却被多次遍历；filter 后未判空就取 front；投影成员类型不匹配。
- **与 ROS2 的关联**：回调内惰性筛选可减少复制，但消息若在回调后释放，view 必须当场消费；跨回调要物化或共享所有权。

## 36 二分搜索边界

- **目标**：手写 lower_bound 风格检索，在空、重复、大数组、越界查询下无 UB，并与 `std::lower_bound` 随机比对 500 次。
- **核心概念**：半开区间 `[lo, hi)` 与循环不变量；返回第一个 `>= x` 的位置，可能等于 size；`mid = lo + (hi-lo)/2` 防加法溢出；每轮区间严格缩小，必然终止。
- **参考实现思路**：写清不变量：`[0,lo)` 全 `< x`，`[hi,n)` 全 `>= x`；循环条件 `lo < hi`，只用 `<` 比较。测试空数组、全相同、严格递增、随机数组；查询取小于最小、等于、介于、大于最大。用 mt19937 生成 500 组排序后与标准库比对下标。
- **关键代码片段**：

```cpp
std::size_t lower_bound_idx(const std::vector<int>& a, int x) {
    std::size_t lo = 0, hi = a.size();          // 搜索区间 [lo, hi)
    while (lo < hi) {
        std::size_t mid = lo + (hi - lo) / 2;   // 防溢出
        if (a[mid] < x) lo = mid + 1;
        else            hi = mid;
    }
    return lo;                                  // 第一个 >= x，可为 size()
}
```

- **验收证据**：随机比对输出 `500 rounds OK`。反例一：`while (lo <= hi)` 且 `hi = n`，读到 `a[n]`，ASan 报错；反例二：`mid = (lo+hi)/2` 在极大索引溢出；反例三：直接返回 `a[lo]` 而不判 `lo == n`，越界。
- **常见坑**：混用闭区间与半开区间；用 `<=` 实现成 upper_bound 语义；重复元素返回任意一个而非首个；对未排序输入调用，前置条件被违反。
- **与 ROS2 的关联**：按时间戳找“第一个不早于 t 的消息”正是 lower_bound；消息缓冲必须保持有序，插入删除后要重新维护或换树结构。

## 37 类型擦除回调

- **目标**：设计 `std::function` 版与模板版两个回调 API，比较对象开销、可替换性与可读性，给出选择依据。
- **核心概念**：`std::function` 做类型擦除，运行期可存任意可调用对象并替换，但可能堆分配且有间接调用；模板回调编译期绑定、易内联、无擦除开销，但实例化膨胀、错误信息更长。
- **参考实现思路**：同一事件源提供两个接口；用捕获 64B 状态的 lambda 触发 SBO 之外的分配，统计耗时与分配次数（可重载全局 operator new 计数），再测小捕获对比。
- **关键代码片段**：

```cpp
struct Msg { int value; };
// API A：类型擦除，可存容器、运行期替换
void subscribe_erased(std::function<void(const Msg&)> cb);
// API B：模板，编译期绑定，易内联
template <class F> void subscribe_tmpl(F&& cb);

struct Handler { std::array<char, 64> state{}; void operator()(const Msg&) {} };
Handler h;
subscribe_erased(h);           // 超过 SBO 时可能堆分配
subscribe_tmpl(std::move(h));  // 无类型擦除开销，但模板实例化进头文件
```

- **验收证据**：输出每次调用 p50/p99 与分配次数。反例一：`std::function` 捕获局部引用，作用域外调用，ASan 报悬垂；反例二：move-only lambda 塞进 `std::function`，C++20 编译失败；反例三：模板 API 定义放 .cpp 导致链接错误。
- **常见坑**：只看平均耗时忽略分配长尾；空 `std::function` 调用抛 bad_function_call；捕获 this 的生命周期；模板 API 造成代码膨胀。
- **与 ROS2 的关联**：rclcpp 订阅回调常用 `std::function` 存储，便于运行期替换与统一调度；极短热路径可评估模板或函数指针，但要权衡 ABI。

## 38 模板错误可读性

- **目标**：用 concept `HasTimestamp` 约束输入类型，正例编译通过，负例编译失败且错误能直接指出缺失或不匹配的接口。
- **核心概念**：concept 检查表达式合法性及返回类型是否满足 `convertible_to`；requires 表达式可组合多条要求。约束只验证语法，单位、单调性等语义仍需文档和测试；`static_assert` 可附自定义提示。
- **参考实现思路**：先写 `requires(const T& t){ { t.timestamp() } -> std::convertible_to<std::int64_t>; }`，函数模板用简写约束。准备 Good、返回 string 的 Bad、只有字段的 FieldOnly、private 成员四类，分别编译并保存诊断首行；错误不直观时加 `static_assert` 包装。
- **关键代码片段**：

```cpp
template <class T>
concept HasTimestamp = requires(const T& t) {
    { t.timestamp() } -> std::convertible_to<std::int64_t>;
};
template <HasTimestamp T>
std::int64_t age_ms(const T& t, std::int64_t now) { return now - t.timestamp(); }

struct Good { std::int64_t timestamp() const { return 42; } };
struct Bad  { std::string timestamp() const { return "42"; } };
static_assert(HasTimestamp<Good>);
// static_assert(HasTimestamp<Bad>);  // 取消注释：约束不满足，诊断指向 concept
```

- **验收证据**：正例 `g++ -std=c++20 -fsyntax-only` 退出码 0；负例退出码非 0，诊断含 “constraints not satisfied” 或 “no matching function” 且指向 concept。反例一：只约束成员存在不管类型，Bad 也通过；反例二：把检查写成运行期断言，负例照样编译。
- **常见坑**：约束过强；`t.timestamp` 与 `t.timestamp()` 混淆；忘记 `<concepts>`；被长模板栈淹没，应先看 “requirements not satisfied” 段。
- **与 ROS2 的关联**：消息适配器可用 concept 统一要求 `header.stamp` 或 `timestamp()`，编译期拒绝不兼容消息，减少运行期模板报错。

## 39 const 接口与线程安全

- **目标**：构造 mutable 缓存场景，用多线程复现数据竞争，说明 const 成员函数不自动线程安全，并引入同步修复。
- **核心概念**：const 只承诺接口不修改可见状态，mutable 成员仍可在 const 函数中修改；多线程调用同一对象的 const 函数仍可能竞争。锁保护共享状态而非函数，atomic 只适合单个独立变量。
- **参考实现思路**：写带 mutable 缓存/计数的 getter；先不加锁，两线程各调用 1e5 次，用 TSan 定位竞争；再加 mutable mutex，复跑确认干净。另测试只锁写不锁读、返回内部引用后解锁等错误修复。
- **关键代码片段**：

```cpp
class Stats {
public:
    int get() const {                    // const 不代表线程安全
        std::lock_guard lk(m_);          // mutable 互斥量保护 mutable 缓存
        if (!cache_) cache_ = compute();
        return *cache_;
    }
private:
    int compute() const { return 42; }
    mutable std::mutex m_;
    mutable std::optional<int> cache_;
};
```

- **验收证据**：`g++ -std=c++20 -fsanitize=thread -g`；修复前输出 “WARNING: ThreadSanitizer: data race” 指向 mutable 成员；修复后无报告且计数确定。反例一：getter 返回 cache 引用，调用方在锁外读取仍竞争；反例二：用 relaxed atomic 保护多字段不变量，逻辑仍错。
- **常见坑**：认为 const 即线程安全；锁粒度过小或过大；递归加锁死锁；用 mutable 绕过设计。
- **与 ROS2 的关联**：MultiThreadedExecutor 可并发调用同一节点回调；节点缓存、统计、参数快照若在 getter 中惰性更新，必须加锁或启动时预计算。

## 40 依赖注入与模拟对象

- **目标**：用时钟接口与 FakeClock 注入时间，使超时逻辑无需 sleep 即可确定性验证。
- **核心概念**：依赖注入把“获取当前时间”从业务逻辑抽离；接口需虚析构；FakeClock 手动推进时间，测试瞬间完成；生产用单调时钟。业务只依赖抽象，不直接调用系统时间。
- **参考实现思路**：定义 `IClock::now_ms`；SystemClock 基于 steady_clock；FakeClock 保存 t 并提供 advance。Watchdog 构造注入 `const IClock&` 与 timeout，`expired(start)` 只做减法比较。测试覆盖差 999ms 未超时、1000ms 恰好超时、时钟回拨的防御。
- **关键代码片段**：

```cpp
struct IClock {
    virtual ~IClock() = default;
    virtual std::int64_t now_ms() const = 0;
};
struct SystemClock final : IClock { std::int64_t now_ms() const override; };
struct FakeClock final : IClock {
    std::int64_t t = 0;
    std::int64_t now_ms() const override { return t; }
    void advance(std::int64_t d) { t += d; }
};
class Watchdog {
public:
    Watchdog(const IClock& c, std::int64_t timeout) : c_(c), timeout_(timeout) {}
    bool expired(std::int64_t start) const { return c_.now_ms() - start >= timeout_; }
private:
    const IClock& c_; std::int64_t timeout_;
};
```

- **验收证据**：整组测试耗时远小于 1s 且边界用例通过。反例一：用真实 sleep 测超时，测试慢且偶发失败；反例二：FakeClock 不前进导致被测逻辑永不超时；反例三：注入临时 `FakeClock{}`，悬垂引用，ASan 报错。
- **常见坑**：忘记虚析构导致 delete 派生对象 UB；系统时钟非单调；timeout 单位混用；测试互相依赖执行顺序。
- **与 ROS2 的关联**：节点时间应经 rclcpp::Clock 获取以支持 /use_sim_time；把时钟抽象注入业务层，可在无 ROS 环境测试超时与定时器。

## 41 配置读取边界

- **目标**：集中解析并验证一组设备配置，返回结构化错误；非法范围、缺键、未知字段可区分。
- **核心概念**：解析与校验分离；错误用枚举分类并带字段名与细节；一次收集全部错误而非首错即返；未知字段策略明确（报错、警告或忽略），不能静默覆盖。
- **参考实现思路**：选简单 `key=value` 行格式，避免引入仓库不存在的库；先查未知键，再查必填键，最后转换并做范围校验；错误 push 到 vector，全部查完再返回 `variant<Config, vector<Error>>`。重复键策略单独定义。
- **关键代码片段**：

```cpp
enum class ErrKind { MissingKey, OutOfRange, UnknownField };
struct Err { ErrKind kind; std::string key; std::string detail; };
struct DeviceConfig { int id = 0; double rate_hz = 0; };
using ParseResult = std::variant<DeviceConfig, std::vector<Err>>;

ParseResult parse(const std::map<std::string, std::string>& kv) {
    std::vector<Err> errs;
    for (const auto& [k, v] : kv)
        if (k != "id" && k != "rate_hz")
            errs.push_back({ErrKind::UnknownField, k, v});
    if (!kv.contains("id")) errs.push_back({ErrKind::MissingKey, "id", ""});
    // 转换失败、rate_hz 范围检查同样 push 错误，最后统一返回
    if (!errs.empty()) return errs;
    return DeviceConfig{std::stoi(kv.at("id")), std::stod(kv.at("rate_hz"))};
}
```

- **验收证据**：三组输入分别得到 MissingKey/OutOfRange/UnknownField，且一次返回多条错误；合法输入返回 Config。反例一：`std::stoi` 对非数字抛异常未捕获；反例二：首错即返掩盖其余问题；反例三：未知键被静默忽略，拼写错误潜伏。
- **常见坑**：转换抛异常；范围边界含不含不一致；单位没写进字段名。
- **与 ROS2 的关联**：设备配置常在启动时集中校验；结构化错误可转日志或诊断消息，避免节点带病运行。

## 42 错误通道契约

- **目标**：比较异常、error_code、variant 三类错误通道，并在一个读取/解析场景中实现清晰的传播与取消语义，确保不吞错。
- **核心概念**：异常适合不可恢复或跨层传播，但回调边界需拦截；error_code 适合可预期的系统/库错误，调用方必须检查；variant 把值或错误放进返回类型，显式无异常。取消应作为独立错误。
- **参考实现思路**：定义 `Error{Timeout,Parse,Cancelled}` 与 `Result<T>=variant<T,Error>`；底层返回 Result，中层用 `get_if` 原样传播，顶层 switch 处理。对照异常版在边界 catch 后转换、error_code 版逐调用检查；测试取消不被误判为 Parse。
- **关键代码片段**：

```cpp
enum class Error { Timeout, Parse, Cancelled };
template <class T> using Result = std::variant<T, Error>;

Result<int> parse_int(std::string_view s);
Result<int> load(std::string_view s) {
    auto r = parse_int(s);
    if (auto e = std::get_if<Error>(&r)) return *e;  // 原样传播，不吞错
    return std::get<int>(r) * 2;
}
void report(const Result<int>& r) {
    if (auto e = std::get_if<Error>(&r)) std::cerr << "error=" << static_cast<int>(*e);
    else std::cout << "value=" << std::get<int>(r);
}
```

- **验收证据**：分别注入非法输入、超时、取消，断言顶层错误码匹配。反例一：`catch(...) { return 0; }` 吞掉所有错误；反例二：忽略 error_code 继续使用未初始化值；反例三：取消被映射成 Timeout，调用方重试逻辑出错。
- **常见坑**：异常穿过 C 回调/线程边界；variant 访问错类型抛 bad_variant_access；只测成功路径。
- **与 ROS2 的关联**：执行器回调中不要让异常逃逸；底层错误应转日志/诊断或状态消息，取消（如 stop_token）显式建模，避免静默丢帧。

## 43 多态组合与可测试性

- **目标**：用组合策略替代按枚举分支的 5 类传感器处理代码，使新增策略不改主流水线，并可用假策略测试。
- **核心概念**：面向接口编程 + 注册表组合；Pipeline 只依赖 `ISensorStrategy`；新增传感器是新增类型并注册，符合开闭原则。组合优于把行为塞进继承层级；虚析构必不可少。
- **参考实现思路**：定义 `convert(Sample)` 接口；Pipeline 持有 `map<string, unique_ptr<ISensorStrategy>>` 并注册，run 只查表调用。测试注入计数型 FakeStrategy，断言调用次数与参数。新增第六类只加新文件与一行注册。
- **关键代码片段**：

```cpp
struct Sample { double value; };
struct ISensorStrategy {
    virtual ~ISensorStrategy() = default;
    virtual double convert(const Sample&) const = 0;
};
class Pipeline {
public:
    void add(std::string name, std::unique_ptr<ISensorStrategy> s) {
        strategies_.emplace(std::move(name), std::move(s));
    }
    double run(const std::string& name, const Sample& s) const {
        return strategies_.at(name)->convert(s);
    }
private:
    std::map<std::string, std::unique_ptr<ISensorStrategy>> strategies_;
};
struct LidarStrategy final : ISensorStrategy {
    double convert(const Sample& s) const override { return s.value * 0.001; }
};
```

- **验收证据**：FakeStrategy 测试通过。反例一：注册同名策略被静默覆盖，应断言拒绝重复；反例二：基类无虚析构，delete 派生对象 UB，ASan 报错；反例三：Pipeline 内仍有 switch，新增类型必须改主流程。
- **常见坑**：策略持有悬垂引用；注册顺序影响行为；为“多态”引入不必要的堆分配。
- **与 ROS2 的关联**：多传感器驱动可用策略/插件注册，主节点不随传感器类型膨胀；结合参数选择策略，注意插件生命周期与线程安全。

## 44 消息版本兼容

- **目标**：为数据包增加可选字段与版本号，使 v1/v2 读写兼容，并明确未知字段策略。
- **核心概念**：版本化报文头 + TLV 自描述字段可跳过未知字段，实现前向兼容；新字段必须有默认值，旧读端不能因未知类型失败；长度必须做边界检查。字段顺序发布后不可改。
- **参考实现思路**：Header 含 magic、version、len；body 用 TLV 编码 `[type][size][payload]`。decode 循环读头与长度，先校验 `off+n <= size`，已知类型还必须校验 `n` 等于字段宽度，未知类型按 n 跳过；缺失可选字段保留默认。并测交叉组合与截断包。
- **关键代码片段**：

```cpp
struct Header { std::uint32_t magic; std::uint16_t version; std::uint16_t len; };
enum class FieldId : std::uint16_t { Temperature = 1, Battery = 2, Rssi = 3 };
bool decode(std::span<const std::byte> body, Packet& out) {
    std::size_t off = 0;
    while (off + 4 <= body.size()) {
        auto type = read_u16(body, off);
        auto n = read_u16(body, off + 2);
        off += 4;
        if (off + n > body.size()) return false;          // 边界检查
        switch (static_cast<FieldId>(type)) {
            case FieldId::Temperature:
                if (n != 4) return false;
                out.temp = read_f32(body, off); break;
            case FieldId::Battery:
                if (n != 1) return false;
                out.batt = read_u8(body, off); break;
            case FieldId::Rssi:
                if (n != 2) return false;
                out.rssi = read_i16(body, off); break; // v2 新增
            default: break;                                // 未知字段跳过
        }
        off += n;
    }
    return off == body.size();
}
```

- **验收证据**：v1→v1、v1→v2（新字段取默认）、v2→v1（未知字段跳过）均通过。反例一：无边界检查越界，ASan 报错；反例二：v2 重排字段后旧读端错位；反例三：未知字段被强转，得到垃圾值。
- **常见坑**：只加字段不加版本；长度用主机字节序；未知字段失败中断滚动升级；默认值语义未文档化。
- **与 ROS2 的关联**：消息演进有兼容规则；在 std_msgs 字节数组承载自定义协议时，应自带版本与 TLV，让滚动升级时新旧节点共存。
