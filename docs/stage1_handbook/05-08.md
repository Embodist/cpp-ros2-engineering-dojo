## 05 Stage 接口与策略组合

- 文件：`stage1/include/dojo/polymorphic_pipeline.hpp`
- 测试：`stage1/tests/test_polymorphic_pipeline.cpp`
- 结果：3/3，ASan/UBSan 通过

### 目标与不变量

抽象 `Stage::process(span<const float>) -> vector<float>`；Bias 加偏置，Clamp 夹紧；Pipeline 按添加顺序串联，持有 `unique_ptr<Stage>`：

1. 空 Pipeline 返回输入的副本。
2. `add(nullptr)` 抛 `invalid_argument`。
3. `ClampStage(low > high)` 抛 `invalid_argument`。
4. 策略对象由 Pipeline 独占，析构自动释放。
5. 组合优先于多重继承：每个 Stage 只关心一个变换。

### 完整实现

```cpp
#pragma once
#include <algorithm>
#include <memory>
#include <span>
#include <stdexcept>
#include <utility>
#include <vector>
namespace dojo {
struct Stage {
    virtual ~Stage() = default;
    virtual std::vector<float> process(std::span<const float> input) const = 0;
};
class BiasStage final : public Stage {
public:
    explicit BiasStage(float bias) : bias_(bias) {}
    std::vector<float> process(std::span<const float> input) const override;
private: float bias_;
};
class ClampStage final : public Stage {
public:
    ClampStage(float low,float high);
    std::vector<float> process(std::span<const float> input) const override;
private: float low_ = 0; float high_ = 0;
};
class Pipeline {
public:
    void add(std::unique_ptr<Stage> stage);
    std::vector<float> run(std::span<const float> input) const;
private: std::vector<std::unique_ptr<Stage>> stages_;
};

inline std::vector<float> BiasStage::process(std::span<const float> input) const {
    std::vector<float> out;
    out.reserve(input.size());
    for (float value : input) out.push_back(value + bias_);
    return out;
}

inline ClampStage::ClampStage(float low,float high) : low_(low),high_(high) {
    if (low > high) throw std::invalid_argument("low > high");
}

inline std::vector<float> ClampStage::process(std::span<const float> input) const {
    std::vector<float> out;
    out.reserve(input.size());
    for (float value : input) out.push_back(std::clamp(value, low_, high_));
    return out;
}

inline void Pipeline::add(std::unique_ptr<Stage> stage) {
    if (!stage) throw std::invalid_argument("null stage");
    stages_.push_back(std::move(stage));
}

inline std::vector<float> Pipeline::run(std::span<const float> input) const {
    std::vector<float> current(input.begin(), input.end());
    for (const auto& stage : stages_) {
        current = stage->process(current);
    }
    return current;
}
}  // namespace dojo
```

### 关键点

- `Stage` 的虚析构保证通过基类指针删除派生对象安全。
- Pipeline 的 `run` 先复制输入，空管道自然返回副本；非空时每级产生新 vector。
- `span<const float>` 只是借用视图，不拥有数据；不能在 Stage 内保存它。
- `add` 拒绝空指针；`unique_ptr` 保证策略对象生命周期跟随 Pipeline。

### 测试推演

| 测试 | 关键路径 |
|---|---|
| pipeline order | Bias(2) 后 Clamp(0,3)：`{-4,0,3}` → `{0,2,3}` |
| empty pipeline identity | 无 Stage，返回输入副本 |
| invalid construction | `Clamp(5,2)` 与 `add(nullptr)` 均抛 |

### 建议反例

- 交换顺序：先 Clamp 后 Bias，结果不同，证明顺序有意义。
- 对空输入运行多级流水线，返回空 vector。
- 自定义 Stage 抛异常：Pipeline 不吞异常，调用方负责恢复。

### 五问卡

- 复杂度：O(阶段数 × 元素数)；每级一次遍历。
- 异常保证：构造/添加在非法输入时抛 `invalid_argument`；process 的异常原样传播。
- 失效/生命周期：Pipeline 拥有 Stage；span 只在调用期间有效。
- 前置条件/UB：Clamp 的 low ≤ high；Stage 的 `process` 必须可重入/线程安全需自行保证。
- 不该用的场景：需要运行时并发执行多级流水线；需要零分配热路径（可改用模板/委托）。

## 06 二进制帧安全编解码

- 文件：`stage1/include/dojo/binary_packet.hpp`
- 测试：`stage1/tests/test_binary_packet.cpp`
- 结果：5/5，ASan/UBSan 通过

### 帧格式

```text
0   1   2       3     4   5      6 ... 5+len   6+len
52  32  ver=1   type  len_hi len_lo  payload     checksum
```

- 固定头 6 字节 + payload + 1 字节 XOR 校验。
- length 为大端 `uint16`；payload 0–1024 字节。
- checksum 从 version 到 payload 末尾逐字节 XOR。

### 完整实现

```cpp
#pragma once
#include <cstddef>
#include <cstdint>
#include <optional>
#include <span>
#include <stdexcept>
#include <vector>
namespace dojo {
struct Packet {
    std::uint8_t type=0;
    std::vector<std::uint8_t> payload;
    bool operator==(const Packet&) const = default;
};

inline std::vector<std::uint8_t> encode_packet(const Packet& packet) {
    if (packet.payload.size() > 1024) {
        throw std::invalid_argument("payload too large");
    }
    const auto length = static_cast<std::uint16_t>(packet.payload.size());
    std::vector<std::uint8_t> bytes(7 + static_cast<std::size_t>(length));
    bytes[0] = 0x52;
    bytes[1] = 0x32;
    bytes[2] = 1;
    bytes[3] = packet.type;
    bytes[4] = static_cast<std::uint8_t>(length >> 8);
    bytes[5] = static_cast<std::uint8_t>(length & 0xFF);
    for (std::size_t i = 0; i < packet.payload.size(); ++i) {
        bytes[6 + i] = packet.payload[i];
    }
    const std::size_t checksum_index = 6 + static_cast<std::size_t>(length);
    std::uint8_t checksum = 0;
    for (std::size_t i = 2; i < checksum_index; ++i) {
        checksum ^= bytes[i];
    }
    bytes[checksum_index] = checksum;
    return bytes;
}

inline std::optional<Packet> decode_packet(std::span<const std::uint8_t> bytes) {
    if (bytes.size() < 7) return std::nullopt;
    if (bytes[0] != 0x52 || bytes[1] != 0x32) return std::nullopt;
    if (bytes[2] != 1) return std::nullopt;

    const std::uint16_t length =
        static_cast<std::uint16_t>((bytes[4] << 8) | bytes[5]);
    if (length > 1024) return std::nullopt;
    const std::size_t checksum_index = 6 + static_cast<std::size_t>(length);
    if (bytes.size() != checksum_index + 1) return std::nullopt;

    std::uint8_t checksum = 0;
    for (std::size_t i = 2; i < checksum_index; ++i) {
        checksum ^= bytes[i];
    }
    if (checksum != bytes[checksum_index]) return std::nullopt;

    Packet packet;
    packet.type = bytes[3];
    const auto payload = bytes.subspan(6, length);
    packet.payload.assign(payload.begin(), payload.end());
    return packet;
}
}  // namespace dojo
```

### 关键点

- 先检查最小长度再索引；`bytes.size() < 7` 直接拒绝。
- 用 `bytes.size() != checksum_index + 1` 同时拒绝截断和尾随字节；不能用 `>=`。
- length 必须先按大端拼装，再检查 ≤1024，最后检查实际长度。
- checksum 覆盖 version/type/length/payload，不覆盖 magic 和 checksum 自身。
- decode 返回 `nullopt` 而不是抛异常；encode 的非法参数抛 `invalid_argument`。

### 测试推演

| 测试 | 关键路径 |
|---|---|
| roundtrip | 编码后解码，Packet 相等 |
| empty frame length | 空 payload 总长 7；length 高/低字节为 0 |
| malformed and trailing | 翻转 checksum / 追加尾随字节 / 只有 1 字节均拒绝 |
| oversize rejects | 1025 字节 payload 抛 |
| wrong version/header | version=2 或 magic 错均拒绝 |

### 建议反例

- 长度字段声称 2 字节但实际只有 1 字节 payload → 长度不匹配拒绝。
- checksum 正确但尾随 1 字节 → 精确长度检查拒绝。
- 1024 字节边界 payload 往返成功。

### 五问卡

- 复杂度：编码/解码 O(n)，n 为 payload 长度。
- 异常保证：decode 不抛（分配失败除外）；encode 只对超长抛 `invalid_argument`。
- 失效/生命周期：decode 复制 payload，不借用输入 span。
- 前置条件/UB：不能跳过长度检查直接索引；length 必须与实际长度一致。
- 不该用的场景：需要抗恶意篡改（XOR 不是加密/强校验，应换 CRC/签名）；需要流式解析分段帧。

## 07 结构化错误与无异常解析

- 文件：`stage1/include/dojo/parse_result.hpp`
- 测试：`stage1/tests/test_parse_result.cpp`
- 结果：3/3，ASan/UBSan 通过

### 语法

严格接受 `seq:<uint32>;value:<int32>`：

- 不允许空格、额外字段、尾随字符。
- 结构错误 → `ParseError::Format`。
- 数字溢出 → `ParseError::Overflow`。
- 正常返回 `Measurement{seq, value}`。

### 完整实现

```cpp
#pragma once
#include <charconv>
#include <cstdint>
#include <string_view>
#include <system_error>
#include <variant>
namespace dojo {
struct Measurement {
    std::uint32_t seq=0;
    std::int32_t value=0;
    bool operator==(const Measurement&) const = default;
};
enum class ParseError { Format, Overflow };
using ParseResult = std::variant<Measurement,ParseError>;

inline ParseResult parse_measurement(std::string_view text) {
    constexpr std::string_view prefix = "seq:";
    constexpr std::string_view separator = ";value:";
    if (!text.starts_with(prefix)) return ParseError::Format;

    const std::size_t sep = text.find(separator, prefix.size());
    if (sep == std::string_view::npos) return ParseError::Format;

    const std::string_view seq_text = text.substr(prefix.size(), sep - prefix.size());
    const std::string_view value_text = text.substr(sep + separator.size());
    if (seq_text.empty() || value_text.empty()) return ParseError::Format;

    std::uint32_t seq = 0;
    const auto seq_result =
        std::from_chars(seq_text.data(), seq_text.data() + seq_text.size(), seq);
    if (seq_result.ec != std::errc{}) {
        return seq_result.ec == std::errc::result_out_of_range
                   ? ParseResult{ParseError::Overflow}
                   : ParseResult{ParseError::Format};
    }
    if (seq_result.ptr != seq_text.data() + seq_text.size()) {
        return ParseError::Format;
    }

    std::int32_t value = 0;
    const auto value_result =
        std::from_chars(value_text.data(), value_text.data() + value_text.size(), value);
    if (value_result.ec != std::errc{}) {
        return value_result.ec == std::errc::result_out_of_range
                   ? ParseResult{ParseError::Overflow}
                   : ParseResult{ParseError::Format};
    }
    if (value_result.ptr != value_text.data() + value_text.size()) {
        return ParseError::Format;
    }

    return Measurement{seq, value};
}
}  // namespace dojo
```

### 关键点

- 先验证结构，再解析数字；避免把格式错误报为溢出。
- `from_chars` 的 `ptr` 必须正好到达末尾；否则说明有尾随字符或非法字符。
- `result_out_of_range` 映射为 `Overflow`，其余错误映射为 `Format`。
- 不使用异常；`variant` 明确表达值/错误两条通道。
- `from_chars` 不接受 `+` 前缀；严格语法下这是可接受的。

### 测试推演

| 测试 | 关键路径 |
|---|---|
| valid measurement | `seq:42;value:-7` → Measurement{42,-7} |
| strict format | 尾随空格、非数字 seq → Format |
| overflow | `seq:4294967296` → Overflow |

### 建议反例

- `seq:42;value:`（空数字）→ Format。
- `seq:42;value:-2147483649` → Overflow。
- `seq:42;value:-7;x` → Format（尾随内容）。
- `seq:-1;value:2` → Format（无符号 seq 不接受负号）。

### 五问卡

- 复杂度：O(输入长度)，只扫描/解析一次。
- 异常保证：不抛业务异常；分配/系统错误除外。
- 失效/生命周期：`string_view` 只在调用期间借用；返回的 Measurement 自持有值。
- 前置条件/UB：数字范围必须由 `from_chars` 检查；不能只检查前缀。
- 不该用的场景：需要容错/宽松解析（应明确允许的空白与字段）；需要保留原始错误位置时，应返回结构化错误详情。

## 08 可关闭的有界阻塞队列

- 文件：`stage1/include/dojo/bounded_queue.hpp`
- 测试：`stage1/tests/test_bounded_queue.cpp`
- 结果：3/3，ASan/UBSan 通过；TSan 通过

### 目标与不变量

`BoundedQueue<T>(capacity>0)`：

1. `push` 在满时等待；`close` 后返回 `false`，不丢已入队元素。
2. `pop` 在空时等待；关闭且排空后返回 `nullopt`；关闭前已入队元素仍可取出。
3. `close` 幂等，唤醒所有等待者。
4. `is_closed` 线程安全。
5. 条件变量必须使用谓词，禁止空转；不得持锁运行用户代码。

### 完整实现

```cpp
#pragma once
#include <condition_variable>
#include <cstddef>
#include <deque>
#include <mutex>
#include <optional>
#include <stdexcept>
#include <utility>
namespace dojo {
template<class T> class BoundedQueue {
public:
    explicit BoundedQueue(std::size_t capacity) : capacity_(capacity) {
        if (capacity == 0) throw std::invalid_argument("capacity");
    }
    BoundedQueue(const BoundedQueue&) = delete;
    BoundedQueue& operator=(const BoundedQueue&) = delete;

    bool push(T value) {
        std::unique_lock<std::mutex> lock(mutex_);
        not_full_.wait(lock, [this] { return closed_ || q_.size() < capacity_; });
        if (closed_) return false;
        q_.push_back(std::move(value));
        not_empty_.notify_one();
        return true;
    }

    std::optional<T> pop() {
        std::unique_lock<std::mutex> lock(mutex_);
        not_empty_.wait(lock, [this] { return closed_ || !q_.empty(); });
        if (q_.empty()) return std::nullopt;
        T value = std::move(q_.front());
        q_.pop_front();
        not_full_.notify_one();
        return value;
    }

    void close() noexcept {
        {
            std::lock_guard<std::mutex> lock(mutex_);
            closed_ = true;
        }
        not_full_.notify_all();
        not_empty_.notify_all();
    }

    bool is_closed() const {
        std::lock_guard<std::mutex> lock(mutex_);
        return closed_;
    }

private:
    std::size_t capacity_;
    mutable std::mutex mutex_;
    std::condition_variable not_full_;
    std::condition_variable not_empty_;
    std::deque<T> q_;
    bool closed_ = false;
};
}  // namespace dojo
```

### 关键点

- `push` 的谓词是 `closed_ || q_.size() < capacity_`：关闭时即使有空位也必须返回 false。
- `pop` 的谓词是 `closed_ || !q_.empty()`：关闭后先把队列排空，再返回 nullopt。
- `close` 先置位并解锁，再 `notify_all`；两个条件变量都要唤醒。
- `is_closed` 用 `mutable mutex_`，const 方法也能加锁。
- `push/pop` 持锁只操作队列，不执行用户回调。

### 测试推演

| 测试 | 关键路径 |
|---|---|
| FIFO and close | 容量 2；close 后 push 返回 false；已入队 10/11 仍可 pop；空后 nullopt |
| invalid capacity | 构造 0 抛 |
| concurrent single producer | 容量 1；生产者 push 0/1/2，消费者 pop 三次；close 唤醒退出 |

### 建议反例

- 两个消费者等待，close 后都返回 nullopt，不挂死。
- 生产者在满队列上等待，close 后 push 返回 false。
- 重复 close 不抛、不丢失已入队元素。

### 五问卡

- 复杂度：push/pop 均摊 O(1)；等待由条件变量挂起，不忙等。
- 异常保证：push 的移动构造/队列分配可能抛；close 幂等；is_closed 不抛。
- 失效/生命周期：close 后对象仍需存活到所有等待线程返回；不要在回调中销毁队列。
- 前置条件/UB：容量 >0；不要在持锁时调用可能重入队列的用户代码。
- 不该用的场景：无界队列（用 deque+mutex）；需要非阻塞尝试（C++20 `try_push/try_pop` 或原子队列）。
