# 工程规范（Dojo 风格，非 C++ 官方强制标准）

## 必守（P0）
1. **所有权必须可解释**：优先值语义 / `unique_ptr`；只有真的共享所有权才用 `shared_ptr`。借用使用引用、指针或 `span`，明确不能越过拥有者寿命。
2. **RAII**：文件/线程/锁/内存/设备句柄必须由对象生命期管理；不在业务调用点 scattered `new/delete`。
3. **异常保证**：每个可能失败的操作列出 basic/strong/no-throw 级别与可回滚状态；析构和清理通常不得抛异常。
4. **函数契约**：标明前置条件、后置条件和失败通道；输入先校验，不以魔法值替代错误类型。
5. **并发正确性**：所有共享可变状态明确同步策略；避免持锁运行外部回调；条件变量必须依赖谓词；退出流程明确。
6. **警告和测试**：至少开启 `-Wall -Wextra -Wpedantic -Wconversion -Wshadow`，不能修改测试预期来掩盖实现问题。
7. **生命周期和回调**：异步回调不得捕获短命对象的悬空引用；ROS2 生命周期/Executor 与线程销毁顺序必须可解释。
8. **安全边界**：长度/整数/格式/协议校验先于内存访问；序列化采用固定宽度整数并显式字节序。

## 建议（P1）
- 统一使用 `override`，需要多态删除的基类加 virtual destructor；优先组合而非无意义继承。
- 参数较大且只读：`const T&` 或视图；小值按值传；需要拥有权转移采用 `unique_ptr` 参数或明确 move。
- 数据结构优先标准库，自己实现容器只作学习、实验或已证明必要的场景。
- `.hpp` 放接口与模板实现，`.cpp` 放非模板实现；使用 target 级 CMake 依赖。
- API 使用 `snake_case` 函数命名、`PascalCase` 类型名、`member_` 私有成员、显式 `noexcept`（有证明才加）。
- 写回归测试：一个成功路径 + 边界 + 失败注入 + 大小/压力测试；用 `std::chrono::steady_clock` 测持续时间。

## Code review Checklist
- [ ] 类型/单位（ms/ns、byte/element、度/弧度）和溢出明确
- [ ] 所有者、借用者、复制与移动时机可说明
- [ ] 失败发生在任意一步仍没有泄漏或不一致状态
- [ ] 所有等待都有唤醒/退出条件；没有隐藏死锁
- [ ] 无捕获 `this` 的悬空异步任务
- [ ] 公开 API 写明错误语义、线程安全语义和性能数量级
- [ ] Debug / Sanitizer / Release 至少根据模块需要覆盖
- [ ] CMake、README、测试指令从新环境可以运行

## 不要过度教条
- 不是所有 getter 都必须 `noexcept`，不是所有地方都要模板化。
- 不要为了遵守“零拷贝”而牺牲所有权清晰度；先测量复制成本。
- 实时控制热路径应避免不可控阻塞/分配，但是否能严格实时要由完整系统、OS 调度和硬件共同决定。
