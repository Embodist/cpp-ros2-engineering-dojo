# 自评体系：每题 20 分，先看正确性后看速度

每项 0～4 分：0=无证据，1=仅知概念，2=有实现但边界薄弱，3=有测试和可解释设计，4=有故障注入/复杂场景的重复验证。

| 维度 | 4 分的证据 |
|---|---|
| 功能正确性 | 可见测试+你新增的正常、空值、极限与失败用例均通过 |
| 生命周期和并发 | 所有权图/线程图，解释回调持有者和停止顺序；适用的 sanitizer 无明显报告 |
| 复杂度和性能 | 时间/空间复杂度和瓶颈量化，有测量环境、次数、基准，不凭直觉断言 |
| 工程可维护性 | API 契约清楚、模块职责单一、可编译构建、错误处理、日志/可读性良好 |
| 理解与复现 | 能脱离 AI 用空白文件重建核心实现并讲清关键设计取舍 |

**通过建议**：>=16/20 且正确性维度 >=3；内存安全/并发致命问题一票否决。高分并不是官方认证。

扩展任务 E01–E05 沿用同一评分维度；E05 的“工程可维护性”额外看干净构建、依赖固定和 CI 可复现。

每次训练 `notes/XX.md` 至少回答：

```markdown
# XX 训练复盘
- 日期/耗时/工具链：
- 目标、不变量、前置/后置条件：
- 拷贝/移动/所有权图：
- 主路径与故障路径：
- 新增的至少两个反例：
- 编译/测试/调试/Sanitizer 命令与输出：
- AI 提出了什么问题？我如何验证？
- 未解决问题与 72h 复写结果：
- 自评：功能 _/4 安全 _/4 性能 _/4 工程 _/4 复现 _/4
```
